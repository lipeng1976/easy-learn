# 伴学 App × ima 混合训练方案（C 方案）落地蓝图

> 决策日期：2026-10-26
> 选定方向：**C = 混合分工**（App 日常打卡 + ima 综合出题）
> 决策依据：成本（ima 判题免费、App 调大模型有 token 费）· 场景（日常高频轻量 vs 周期综合）· 设备（李雨霏纯血鸿蒙，ima 宜由家长操作）

---

## 0. 一句话定位

**伴学 App 是错题的唯一输入源和日常训练入口；ima 只做错题镜像归档 + 周期性综合出题（家长操作，免费判题）。** 两套系统同源（都基于 App 错题），不互相录入，避免双数据源漂移。

---

## 1. 总览与数据流

```
[伴学 App 录入错题] ──同步──> [服务端 PG 5433] ──导出脚本──> [ima·错题档案]  (只镜像，不录)
                                                  │
            ┌─────────────────────────────────────┘
            ▼
[App 每日概念训练 v1]            [ima 综合出题] ──李雨霏做──> 拍照回传 ──ima 免费判题
 本地题库36题 + 错题加权            家长基于错题档案出题
 李雨霏唯一日常入口                ima 只由家长操作
```

- 李雨霏**只碰 App**（日常训练）。
- ima 综合卷**由家长**在 PC/微信操作生成，孩子不碰 ima —— 规避她纯血鸿蒙跑 ima 的隐患。
- 错题数据**以 App 为唯一源**，ima 错题档案是下游镜像。

### 2.3 设计要点（防静默失败）

- **每天一组、同种子**：选题只由「学生 + 日期」决定，上午做的不因下午重进页面而变。
- **切 tab 守卫**：已在答题中且无提交时，重进页面不清空已选选项（否则「答到第三题切出去，前两题白选」）。
- **整组提交**：一组题要么整组落库，要么整组不留 —— 半组历史会让「最近一次做错」落到残记录。
- **错题加权对齐**：题库 `knowledge` 字段刻意对齐错题表既有字符串（如「列方程解应用题」），两边词不一致时加权静默失效。
- **只本机**：训练记录不上云（与 `knowledge_tip` 同路），避免跨家庭互读训练流水。

## 3. ima 侧综合出题 SOP（家长操作，无需开发）

**前提**：错题档案已同步（导出脚本跑过，见第 4 节）。

1. 打开 ima.qq.com 或微信小程序，进入「李雨霏的知识库」。
2. 对话框输入（建议 `@李雨霏的知识库` 限定范围）：
   > 基于错题档案，针对她的薄弱点（列代数式 / 用字母表示数、列方程解应用题）出一份综合练习，10 题左右，含「文字→式子」转换和简单列方程应用题，附答案与解析。
3. ima 生成练习（通常为 HTML 闯关卷，浏览器打开自动批改；或文字题）。
4. 让孩子做；若为文字题，做完**拍照上传 ima** 让其判题（**免费**，走 ima 模型）。
5. 看 ima 反馈的薄弱点，决定是否下周加练。

**频率建议**：每周末 1 份综合卷；日常 App 每日训练照常，两者不冲突。

## 4. 数据同步节奏

- **工具**：`tools/export-mistakes-ima.mjs`（已验证：题干数 == 错题数、同义词归并、空学生不产空文件）。
- **触发**：每次综合出题前跑一次，保证 ima 错题档案是当周最新。
- **后续**：可加定时任务（如每周自动导出），当前手动即可。

## 5. 隐私红线（不可破）

- 导出只放「知识点 + 错因」摘要，**不带姓名、不带原题照片**。
- 错题档案**只进个人库**（非共享库；共享库他人可见）。
- App 训练记录**只本机，不上云**。

## 7. 风险与待定

- **ima 鸿蒙原生支持未知** → 综合卷由家长在 PC / 微信操作，孩子不碰 ima，规避设备风险。
- **ima 出题质量黑盒** → 首份综合卷人工审题，不过度依赖；与 App 错题本口径不一致时以 App 为准。
- **双系统弱项口径** → App 错题本是权威源，ima 仅作参考；若后续 ima 出的题与 App 训练重复，以 App 每日训练优先。

## 8. 题库补齐记录（2026-10-26）

- **补前问题**：`drill_bank` 原 36 题，知识点标签是通用「翻译概念」（用字母表示数/列代数式…），与李雨霏错题表 `review_mistake.knowledge_point` 的真实字符串（有理数混合运算/列方程解应用题/解一元一次方程…）**对不上** → 选题加权静默失效（加 0 不报错，个性化悄悄不存在）。
- **根因：知识点漂移**：错题本是模型自由文本，同一概念多写法并存（`解一元一次方程`/`方程求解`/`解方程` 三词同义；`有理数*` 碎成十几个变体）。
- **两处修复**：
  1. `drill_selector.dart` 新增 `kKnowledgeAlias` + `normalizeKnowledgePoint()`，在「权重来源」一侧把自由文本折成规范词（canonical）。
  2. `drill_controller._loadMistakeWeightsFromDatabase` 聚合前先 `normalizeKnowledgePoint`，保证加权键与题库 `knowledge` 一致。
- **补齐题库**：新增 35 题（共 71 题），按她的真实弱项簇贴规范词：
  · 有理数混合运算 11（基础5/进阶3/综合3）· 列方程解应用题 7 · 解一元一次方程 4 · 图形想象 11（预判薄弱点，无错题也入池）· 幂的运算 2。
- **验证**：`analyze` 无 error/warning；`drill_bank_test` 8/8（新增「弱项 canonical 覆盖」断言）；全量回归 **1098 通过 / 0 失败**。
- **暂未做**：大模型离线扩库（用户决策「暂时不扩」）。

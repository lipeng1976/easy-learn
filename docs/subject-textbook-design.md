# 学科教材 → 出题范围（设计）

> 2026-11-12。配套 `textbook-ima-format.md`（家长怎么准备文件）、`subject-board-design.md`（看板版面）。
> 迁移 `027_subject_textbook.sql` + `029_book_grade_term.sql`，路由 `src/routes/textbook.js`，解析 `src/textbook_import.js`。

---

## 1. 要解决的问题

原来的「学科范围」是家长**手打的 ≤6 条文本**（`subject_scope.points`），与 ima 里的教材毫无关系。
后果：

- 家长要自己想「这周该练什么」，还得记得孩子学到第几章；
- 教材就在 ima 里，App 却完全不知道它存在；
- 手填 6 条与整本书的章节结构对不上，也没法「跟着学校进度走」。

目标：**ima 里的课本 = 出题范围的来源**，家长只配一次「哪本书、从第几节、每天几节」。

---

## 2. 三层结构（边界画死）

```
ima 知识库                      PG                          配置                 出题
教学资料/教材/数学/*.md  --导入-->  subject_book / subject_unit  --选书--> subject_scope --> generate
   （骨架 MD）                    （节 + 考点清单）              （书 + 游标 + 题量）
```

**红线**：

1. **App 从不解析 PDF**。PDF 只作为 ima 的输入；App 与 ima 之间唯一的交换格式是结构化 MD。
2. **出题时从不读 ima**。教材只在导入那一刻被读一次，之后全走 PG。
3. 教材是**可选能力**：没开通 ima、没导入书、027 没迁移，一律静默退回「家长手填 / 范围页配置」；
   两者都没有时，出题会**明确报错并指出下一步**（不再拿错题本兜底 —— 错题本属于复习那条线，
   见 `doc/review-vs-plan.md`）。

第 2 条不是洁癖。ima 会 401/403/超时，家长也会删文件；出题是主链路，主链路依赖一个
可能不存在的服务，症状就是「某天一科都出不了题」且没有可解释的错误。

## 3. 表

### `subject_book`

| 列 | 说明 |
|---|---|
| `id` | `tb_<uuid>` |
| `student_id` / `subject` | 一科可有多本（七上 / 七下） |
| `title` / `unit_count` | 显示与越界校验 |
| `grade` / `term` | **书本身的属性**（不是 scope 的属性）：这本属于哪个年级学期。导入时由家长在弹窗里**显式选**，默认填当前学生的年级学期。空串 = 老数据 / 没标。详见 §3.5 |
| `source` / `source_media_id` / `source_path` | 来源（目前只有 ima）。`(student_id, source_media_id)` 有部分唯一索引 → 重复导入不建两本 |

### `subject_unit`

| 列 | 说明 |
|---|---|
| `unit_no` | **文档顺序**（1 起），不是从标题解析的章号 |
| `title` | 「第1章 有理数」 |
| `summary` | 「正数、负数、数轴、相反数、绝对值」——出题时切成知识点 |
| `page_hint` | `p23` → `23`，只用于下拉显示 |

**不存正文**：出题要的是「考什么」；正文会让模型抄原题、prompt 变几 MB、范围失控。
公式与插图在 MD 里本来就会丢（见 `textbook-ima-format.md`），存半成品比不存更危险。

### `subject_scope` 扩三列

| 列 | 说明 |
|---|---|
| `book_id` | 空 = 没配教材，走老路径 |
| `start_unit_no` | **既是起点也是游标**：出一次题往后推 `units_per_day` 节 |
| `units_per_day` | 1 / 2 / 3（CHECK） |

为什么起点和游标是同一个数：两个数一出现就会有「改了起点但游标没动」这类
只在一处生效的 bug，而症状是「出题范围跟配置对不上」。

## 3.5 年级 / 学期：资源分两类

孩子会一直用这个 App，年级会变、教材会更新。所以**资源按「是否跟教学大纲走」分两类**：

| 类别 | 例子 | 要不要按年级学期区分 | 为什么 |
|---|---|---|---|
| 跟大纲走 | 教材、词表 | **要** | 七上的题给初二做就是错的；换年级必须换一本 |
| 跟着孩子走 | 阅读书、错题本、过程性数据 | **不要** | 阅读是在目录里选书，错题本每条已带年级快照，跟大纲无关 |

**落地的约定**：

1. `subject_book` / `word_book` 加 `grade` / `term` 列（书本身的属性，不是 `subject_scope`
   的属性）—— 迁移 `029_book_grade_term.sql`。`reading_book` 故意不加（阅读不分年级学期）；
   `review_mistake` 不拆表，每条错题已有年级/学期快照（记**学生当前年级**）。
2. 年级学期来自导入时的**显式选择器**，**绝不解析 ima 路径**—— ima 里文件夹命名千奇百怪
   （`七上`/`7上`/`七年级上册`/`2026秋`…），解析必碎。默认填当前学生档案的年级学期，家长改了才变。
3. **ima 软约定（人类浏览层，非系统契约）**：`教学资料/教材/<学科>/`（**只到学科这一层，
   不要按年级建子文件夹**）、`教学资料/Wordlist/` 平铺、`教学资料/English/` 平铺。
   导入代码只找 `教材/数学` 这样的学科夹、只下探一层、不递归。年级写进文件名和
   md 首行书名即可，系统只认「导入时家长选的 grade/term」，不认路径。详见 `textbook-ima-format.md` §四。
4. **年级只有一套规范词**：`kGradeOptions` = `一年级…六年级 / 初一 / 初二 / 初三 / 高一 / 高二 / 高三`，
   与学生档案页、错题本年级归档顺序**逐字一致**，三处都引用同一份常量（11-13 收单点）。
   `七年级 / 八年级 / 九年级`（以及 `7年级` 等）是**同一个年级的别名**，进 `kGradeAliases`，
   由 `canonicalGrade` 归一；比对、展示、导入弹窗预填、落库都只看归一后的值。
   🔴 11-12 曾在这里另造一套「七年级…」而档案是「初一」：家长导入选了七年级，
   同一个年级被判成「不匹配」，弹窗还把「初一」预填成「一年级」。历史行不 UPDATE，靠归一兼容。
5. **配置页匹配预警（刻意宽松）**：`gradeTermMismatch(book, profile)` 先归一再比；
   书或档案任一方为空串 / `未填写` 时返回 `false`（「不知道」而非「不匹配」）——
   报「不匹配」只会逼家长去改一个他不知道该填什么的值。
   只有两边都有值、归一后确实不等才显示橙色横幅「这本是 X，但当前年级是 Y」并给「去换书」。

> 错题本每条年级快照记「学生当前年级」还是「书所属年级」：拍板记**学生当前年级**——
> 错题是按孩子当下水平归的，不是按某本书归的；书的年级只用于「选书时预警」，不回写错题。

## 4. 出题时的优先级

```
教材（配了书 + 这几节有内容）  >  发起页临时勾的知识点  >  范围页存下的 points
```

**错题本不在这条链上。** 计划只从「教材」或「家长指定」取内容；错题本属于「复习」，
它的入口是「由错题引出举一反三」。把错题本当兜底，会出现两种界面看不出来的混淆：
①历史这类还没学过的科目永远没有错题，于是永远出不了题；
②孩子的错题悄悄出现在「按教材进度」的打卡里，家长以为课本生效了。

代码在 `generateCheckin`：

```js
const textbook = await resolveTextbookPoints(client, studentId, subject, MAX_SEED_POINTS);
if (textbook) requestedPoints = textbook.points;
else if (requestedPoints.length === 0) {
  // 学生自发起不带知识点：读家长在范围页存下来的那份
  requestedPoints = await scopePointsOf(client, studentId, subject);
}
if (requestedPoints.length === 0) throw noSeed(...);
```

`collectCheckinSeeds` 仍然会查，但只用来给这几个知识点补上「错过几次 / 错因」
（模型据此调难度），**不再作为来源**。

**教材优先**是刻意的。两套范围混在一起的话，家长看到的是「我明明配了课本，
考的却是手填的那条」，而界面上没有任何线索说明为什么。

### 「这几节有内容」= 有考点，或者有标题（11-12 事故）

`resolveTextbookPoints` 原先只在 `summary` 拆得出考点时才算命中，否则返回 `null`。
真实数据里中国历史 22 节**一行「考点：」都没有**（骨架只写了目录），于是整本书
从没生效过：出题静默退回错题本，而历史这种**还没学过、不可能有错题**的科目
于是每次都 400 —— 文案还是「先录几道错题」，把家长引向一条不存在的路。

现在一节至少产出一个点：

- 写了考点 → 拆考点（老行为）；
- 没写考点 → 用**章节标题**（`第 7 课 百家争鸣`）。标题自带课号与主题，模型能直接出题；
- 标题是**板块名**（`阅读` / `写作` / `综合性学习` / `名著导读` …）→ 跳过，取下一节。
  语文目录就是 `阅读` → `1 春` → `2 济南的冬天`：拿「阅读」当知识点，模型会出
  「阅读方法」这类与课文无关的通识题，而题目本身通顺、界面上看不出跑偏；
- 标题和考点都空 → 跳过这一节；整次都空才返回 `null`。

游标因此改成 **`实际采用的最后一节 + 1`**，不再是 `start + units_per_day` ——
跳过板块名时按配置步长盲推会白跳一整节正文。SQL 侧也多取几节（`units_per_day × 4`），
否则连着几个板块名就一个点都凑不出来。

`titleOnlyPoints` 标出哪些点是标题顶的，`generateCheckin` 会打一行日志 ——
以后「历史出的题跑偏了」，先看这行就知道是骨架缺考点，而不是模型的问题。

另外两处顺带收紧：

- 范围比较**忽略空白**（`knowledgeKey`）：模型把「第 7 课」写成「第7课」不再被当成
  越界整单丢掉；命中后 `knowledge` **改回请求里的原文**，因为客户端与错题归档
  都按这个字符串关联。
- 一条范围都没有时的报错**按科目说**：「历史还没有出题范围：给这一科选一本教材
  （按章节出），或者填两个知识点。」`details.reason = no_seed`、`details.subject` 带上，
  客户端据此把家长送到配置页，而不是停在一句「错题本还是空的」上。

**顺带修掉的老 bug**：`collectCheckinSeeds(client, studentId)` 原来没传 `subject`，
会把全科错题聚成一锅，然后拿「数学」的科目名去出「语文」的知识点 ——
学生自发起、家长又没配范围时就会遇到。

### 游标推进

只在 `insertCheckinQuiz` **成功之后**推进（`advanceUnitCursor`）：

- 失败还推 → 家长点一次没出成、再点一次，范围已经跳了一节，那一节从此再也不会被考到；
- 越过最后一节**停在最后一节**，不回绕（回绕会让「快考试了」的家长收到第 1 章）；
- 推进失败只打日志，不让这次出题失败 —— 下次还考这一节，比这次报错好。

## 5. 端点

| 方法 | 路径 | 语义 |
|---|---|---|
| GET | `/data/textbook/books?studentId&subject` | 恒 2xx。已导入的书 + ima 里可导入的 md |
| GET | `/data/textbook/units?studentId&bookId` | 章节列表 |
| POST | `/data/textbook/import` | 下载 → 解析 → 落库；0 节直接 400 |
| POST | `/data/textbook/delete` | 删掉一本已导入的书（换版 / 导错了重来） |

`books` 的 `reason`：`ima_unavailable` / `folder_missing` / `ima_read_error`，空 = 正常。
客户端据此决定说哪句话，而不是统一「加载失败」。

`import` 幂等且**保留 book.id**：`subject_scope.book_id` 指着它，删掉重建会让家长的
「从第 3 节开始」静默失效（配置还在，指向一个不存在的书）。

### 换教材 / 删旧书（11-13）

ima 里换了一份新骨架 MD 时，若**重新上传生成了新 media id**，再导入就会多出一本书：
`import` 只按 `source_media_id` 幂等，不会把两本书合并。配置页会并排列出两本，
家长不知道选哪本。

- **App 侧的导入记录**：配置页「教材 → 删除已导入」→ 选书 → 二次确认。
  `delete` 在同一个事务里删 `subject_unit` + `subject_book`，并清掉指向它的
  `subject_scope.book_id` / 把 `start_unit_no` 归 1。漏清 scope 的症状是
  「界面还显示教材、出题却静默退回手填范围」。删的是当前选中的书时，客户端
  **必须同步清掉本地 `_scope`**，否则随后点「保存范围」会把已删的 id 写回去。
- **ima 侧的原文件**：开放接口只有「创建 / 列举 / 读取」，**没有删除文件的能力**。
  旧文件删不掉是接口限制，只能在 ima 客户端里删除或移出 `教学资料/教材/<学科>/`。
  留着不影响出题（教材已落库），但会一直出现在「从 ima 导入」的候选列表里，别再点它。

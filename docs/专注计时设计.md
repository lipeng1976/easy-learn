# 作业专注计时（2026-10-19）

> 一句话：学生在作业卡片上点「专注计时」，进入一屏**只有时间**的界面；
> 暂停不计入，离开应用自动暂停，结束后把「真正在学的时间」写进这份作业的实际用时。
>
> 2026-10-19 下午补了两块：**知识点提示**（从当前科目的错题本归纳，计时页轮换显示）
> 与**连续 40 分钟休息提醒**（可设置，变色 + 朗读 + 字幕）。见第九、十节。

## 一、要解决的不是「监督」，是「时间感」

学生对自己的作业用时几乎没有概念 ——「这篇作文写了两个小时」通常是猜的。
这一屏把时间放到**屏幕上最大的位置**，让「我这道题花了多久」变成看得见的事实。

所以这一屏**刻意没有**分数、排名、「比昨天慢了」这类评价。加了任何评价，
学生就会为了好看的数字而计时，那个数字立刻失去意义。

## 二、计时口径（三条，界面必须说得出来）

| 规则 | 理由 | 界面上的说法 |
|---|---|---|
| **暂停不计入** | 上厕所、被叫走、接电话都不是学习时间 | 暂停时数字冻结，状态行写「已暂停」 |
| **离开应用自动暂停** | 不这么做，「手机放桌上两小时」会被记成学习两小时，而这个数会进学习报告 | 「已暂停 · 你刚才离开了应用」 |
| **大数字是「本次」** | 学生要分清「这一次」和「总共」 | 底部小字写「此前已记录 X / 结束后将是 Y」 |

自动暂停只认 `AppLifecycleState.paused` / `hidden`。`inactive` **不算** ——
它在来电横幅、下拉通知栏时也会触发，当成离开会让计时眨眼间被暂停。

## 三、时间从哪来：墙钟差，不是 tick 计数

`FocusTimerService` 用 `DateTime` 相减累加，ticker 只负责「让界面重画」。

按 tick 数（每秒 +1）计时的话，定时器漂移 + 系统省电 + 前台队列积压，
一次 40 分钟的作业能少算几分钟，而且**没有任何报错**。

系统时间被回拨（学生手动改时间 / 时区跳变）时，差额是负数 —— 夹到 0，
**不倒扣**已累计的部分。倒扣的话学生会看到时间往回跳。

## 四、保存在什么时候（四处，写的都是总量）

| 时机 | 为什么 |
|---|---|
| 手动暂停 / 自动暂停 | 检查点。进程被杀最多丢「暂停之后的几秒」，而不是整段 |
| 离开页面 | 同上 |
| 「结束并保存」 | 终态；**成功才清会话**，失败保留会话可重试 |
| 关闭页面（dispose 兜底） | 不留一个「还在跑」的会话 —— 卡片会永远显示「计时中」 |

⚠️ **写的是「此前记录 + 本次」的总量，不是增量**。增量在网络重试下会重复累加
（请求超时但服务端已写成功，客户端重发就加两遍），症状只是「时间莫名变多了」。
整份覆盖是幂等的。

## 五、同时只允许一份作业在计时

两段并行计时会让「实际用时」失去意义：同时做两科、各记一小时，加起来两小时，
而学生只坐了一小时。开始第二份时先「结束上一份」，并把上一份保存好 ——
静默丢掉上一份等于少记，自动累加到新作业上等于把两科记成一科。

## 六、数据链路

| 层 | 改动 |
|---|---|
| 模型 | `HomeworkItem.actualSeconds`（秒，`0` = 从未计时，不是「用了 0 秒」） |
| 客户端库 | DB **v26**：`homework.actualSeconds INTEGER NOT NULL DEFAULT 0`；迁移**先判表在不在** |
| 客户端库（提示） | DB **v27**：`knowledge_tip` + `app_setting`，**只在本机**（见 9.3） |
| 服务端库 | 迁移 `013_homework_actual_seconds.sql`（`IF NOT EXISTS`，可重跑） |
| 服务端接口 | `PATCH_SPEC.actualSeconds`（负数 400，`null` 归 0）；`GET /data/homework` 的 select 带上这一列 |
| 共享模型 | `HomeworkPatch.actualSeconds` setter（掩码语义，本地/上行两种编码都由 `_render` 处理） |

不回填历史数据：这一版之前没有计时记录，用 `estimatedMinutes * 60` 填进去
等于伪造「孩子实际用了多久」，而这份数字会进家长端与报告。

### 6.1 家长端怎么读这个数（2026-10-20）

家长端「作业信息」在**预计耗时**下面多了一行**实际用时**。

**数据链路本来就是通的**：服务端 `listHomework` 的 select 早就带了 `actual_seconds`，
`rowsToApi` 转成 `actualSeconds`，客户端 `_fromRow` 也早就解析了它。缺的**只有界面** ——
家长端从头到尾没画过这一行。这是「数据通了、界面没接」的典型形态：任何一层单看都是好的。

两条口径（比「显示出来」更容易做错）：

| 值 | 界面 | 为什么 |
|---|---|---|
| `actualSeconds > 0` | `formatStudyTime(...)`（如 `32 分 15 秒`） | 孩子按下计时结束那一刻写进来的总数 |
| `actualSeconds == 0` | `孩子未开启计时`（灰色、非加粗） | 它的含义是**没有数据**，不是「做了 0 秒」 |

⚠️ **绝不能显示「0 秒」**。在家长眼里「实际用时 0 秒」是一句断言（「孩子一秒没做」），
而系统实际表达的是「不知道」—— 孩子可能压根没开计时，也可能开了立刻退出。
把「不知道」渲染成一个具体的数，是静默失败最典型的藏身处。

⚠️ **不能用 `estimatedMinutes` 兜底**。那会把「计划用时」伪装成「实际用时」，
而这两个数摆在一起看才有意义（家长要判断的是「孩子磨蹭了吗」）。

判据 `test/parent_homework_actual_time_test.dart`（**6 条**）：2 条数据链路
（1935 秒原样读出、没计时读回 0 而不是被填成预计耗时）+ 4 条界面
（显示时长、换一份数据页面跟着变、没计时显示「未开启」且不出现 0 秒、预计耗时没被挤掉）。
证伪 3 条：① 整块删掉 → 恰好 4 红；② 一律按秒数显示 → 恰好 1 红（「没计时」那条）；
③ 把值写死成 `32 分 15 秒` → 恰好 2 红 —— **用相同时长的那条仍绿**，
只有换了数据的用例才抓得到硬编码，这就是为什么必须有第 2 条不同数据的用例。

## 八、已知限制

- 计时会话**只活在内存里**：进程被杀之后那一段丢失（检查点把损失限制在几秒）。
  落盘会先逼出一个没有答案的问题 ——「进程被杀的那段时间算不算学习」。
- **真机未验收**：本机没有 Android 设备，暂停/继续/熄屏自动暂停、休息提醒的**出声**、
  提示区的首次加载（联网一次问模型）、**计划计时与临时打卡这两条新路径**都只在
  widget 测试里跑过。
- 网页版不做「屏幕常亮」（`ScreenAwake` 在非 Android 上是空操作）。

## 九、知识点提示（2026-10-19 下午）

### 9.1 它是什么、不是什么

学生正在做题的那一屏，下方留一块区域，**按当前作业科目**轮换显示一句话：

> 「一元二次方程」你已经错了 3 次：先用一句话说出它的定义，说不出来就先翻书。

这不是讲解。讲解是「这道题怎么解」，一节五步；提示是「这一类题最该记住哪一句」。
塞一段讲解进来会把注意力从题目上拽走，而这一屏的全部意义就是让他专心做题。

### 9.2 三条优先级（先显示，再变好）

计时页**不能等模型**：真机上 30 秒窗口，学生看到的会是一张空白卡片，
而空白会被理解成「没这功能」。

```
1. 同一份错题池生成的模型提示，且没过期（72h）→ 直接用，不发请求
2. 有旧提示但错题池变了 → 先显示规则提示，后台重新生成
3. 什么都没有             → 先显示规则提示，后台请求模型
```

规则提示（`KnowledgeTipSource.rule`）**不编造知识内容**，只做两件能保证为真的事：
复述真实的错题次数，并把知识点变成一个能当场回答的问题。它和模型提示
在数据层是分开的 —— 界面长得一样，语义不一样。

### 9.3 缓存与失效

- 存本机：`knowledge_tip`（`studentId + subject`）。**不进云库** —— 提示是从
  「这台设备上这份错题池」归纳的，写进共享库会让 A 学生的提示出现在 B 的计时页。
- 每行带 `signature`（`subject|知识点:错题次数;…` 排序后拼接）。读缓存时比一次，
  错题池变了就不用旧提示 —— 比「按时间过期」准：学生刚补录一道错题，
  下一次就该看到新的。
- **降级产物不写缓存**：一次断网按当前指纹写进去，等于三天内都不再重试，
  界面看起来正常、只是永远只有自检问句。失败后 5 分钟冷却，避免每开一次页面等 30 秒。

### 9.4 服务端

新增 `POST /ai/review/tips`（`kind: reviewTips`，reasoning 档）。

- 入参：`subject` + `items[{knowledgePoint, wrongCount, wrongReason}]`，最多 12 个知识点。
- 服务端**再合并一次**重复知识点并保留「错得最多」的那条：不能指望客户端守规矩，
  重复三条会让模型把同一句话写三遍，学生连点「换一条」看到的还是同一句。
- 契约要求 `knowledgePoint` 必须原样来自请求。客户端解析时：挂不回去的**单条丢掉**，
  但若整批都挂不回去，判违约并重试（否则会显示一堆与错题本无关的提示）。
- 走 reasoning 而不是 light：这几句话会被学生当成要点记住。它有缓存，
  一个科目三天才生成一次，省这一档不值。

## 十、连续 40 分钟休息提醒

### 10.1 口径

| 问题 | 答案 |
|---|---|
| 算的是哪个时间 | **连续**专注时长，不是本次会话总时长 |
| 暂停算不算休息 | 暂停 ≥ **3 分钟**才算。短短的停一下不算 —— 否则学生按一下暂停就能绕开提醒 |
| 提醒频率 | 到点一次；点「再学 10 分钟」推后 10 分钟；点「好，去休息」清零并暂停 |
| 阈值 | 25 / 40 / 50 / 60 分钟 / 不提醒，默认 **40**。在计时页右上角直接改，存本机 `app_setting` |

「好，去休息」会**顺带暂停计时**：学生按了这颗键就是准备起身，
只清零不暂停的话，他走到客厅的十分钟会被记成学习时间 —— 而那恰恰是本功能
最想从「学习时长」里排除的一段。

### 10.2 提醒怎么发生（三条通道，缺一不可）

1. **变色**：整屏渐变从冷蓝转暖橙，大数字变琥珀色。不改布局、不打断阅读，
   余光能看见「有件事发生了」。
2. **声音**：系统 TTS 念一句「已经连续专注 40 分钟了，站起来走两步，看看远处」。
   没有语音引擎 / 网页版时退回 `SystemSound.alert`；两者都不可用时静音 —— 这是对的。
3. **字幕**：原地弹出提醒卡，写清「已经连续专注 N 分钟」+ 两个按钮。

到点休息时**只显示提醒卡**，知识点提示先让位：两块都留着的话，小屏上按钮会被
挤到需要滚动才能点到的位置 —— 一条让你休息的提醒，还得先滑一下，本身就不友好。

### 10.3 出声只在一处

只在 `restDue` 的监听里调用，**不要放进 `build()`**。`ValueNotifier` 只在值真的
变化时通知，所以这条路径天然「每次到点只念一次」；写进 build 会在每次重画时重念，
学生只能把手机静音。判据见 `focus_timer_page_test.dart` 的「只念一次」——
把这一句移到 build 里，那条用例立刻变红（实测 2 条播报）。

### 10.4 小屏排版

`LayoutBuilder` 在高度 < 720dp 时切紧凑档（数字 76→58、主按钮 84→68、间距收紧）。
600dp 高的屏上，固定排版会把提醒卡的按钮挤出可视区。

## 十一、计划计时与临时打卡（2026-10-19 晚）

### 11.1 为什么计划也要计时

计划里最常见的条目就是「每天阅读 20 分钟」。它和作业一样需要一个「到底花了多久」
的答案，而 `homework.actual_seconds` 只挂在作业上 —— 没有计时的话，
「今天读了多久」只能靠打卡那一个勾来回答，而勾只能说「做了」，说不出「多久」。

### 11.2 `FocusTarget`：把「在计什么」和「存到哪」分开

一个目标 = `kind` + `id` + `title` + `subject` + `recordedSeconds`。计时这件事
对三种目标一模一样，只有**保存去哪**不同，而那是 `StudentController` 的事：

| kind | 写到哪 | 基数 |
|---|---|---|
| `homework` | 镜像总数进 `homework.actualSeconds` **+** 写一条流水 | 作业上已有的实际用时 |
| `plan` | 只写流水 | **只算今天**（计划按天重复，历史总量没有意义） |
| `free` | 只写流水，`sourceId` **留空** | 无 |

`sourceId` 留空而不是拿标签凑：标签会改（「其它」明天改叫「阅读」），
而 id 是要拿来汇总的键 —— 键会变的汇总，等于没有汇总。

### 11.3 流水为什么是「一次会话一行」

计时页在暂停、离开应用、结束时各写一次（检查点）。每次**新增**一行的话，
暂停三次就变三条、时长翻三倍，而界面只是「今天读了 1 小时」—— 没有任何报错。
所以 `id` 由客户端开会话时生成（`fs_<微秒>`），存储层按主键 upsert。

问题随之而来：客户端能指定 id，就要防「拿别人的 id 来写」。
而这个**不能在写之前查** —— RLS 会把别人的行藏起来，于是「查不到」有两种含义
（本来就没有 / 是别人的）。所以写成：upsert 带 `where student_id = excluded.student_id`，
写完之后再读一次；读不回来就是撞了别人的 id，回 403。

### 11.4 临时打卡的选项为什么是固定几个

自由输入会得到「看书」「阅读」「读课外书」三个标签，于是「今天读了多久」
在统计里被劈成三份，每份看起来都不多。选项收在一处定义（`FocusQuickLabels`），
空串 / 全空白归一到「其它」。

### 11.5 入口只有一处

`FocusTimerLauncher.open()`：作业页和计划页都走它。「同时只允许一段计时」
这条规则只有一份才成立 —— 两处各写一遍的话，其中一处迟早忘了先结束上一段，
表现是「数学的时间跑到语文上」，而两张卡片都在正常显示各自的用时。

已有会话时先问一句（结束并开始 / 先不开始）；**保存失败就不清会话**，
那段时间还在内存里，学生回到卡片还能再存 —— 清掉才是真的把它弄丢了。

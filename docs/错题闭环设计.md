# 错题闭环设计（2026-10-19）

> 目标：把「错题」从**作业批改的副产品**升级成**一条可主动维护的学习主线**。  
> 本文件是施工图，不是宣传稿；每一节都写清「现状是什么、为什么不够、改成什么、怎么验收」。

## 0. 一句话结论

> **实施状态（2026-10-19）**：P1 数据地基 + 单题拍照录入**已完成**；P2 的「讲解带题干 + 公式渲染」  
> **已完成**，P2 剩余（讲解带原图 / 视觉档 / 语音）与 P3、P4 未做。逐条勾选与证伪记录见 §9。  
> 判据基线：客户端 817 · 网关 229 · 数据服务 270 · `flutter analyze` 0 error。

现有闭环只差三块地基：**录入入口太窄（只有纯文字）、错题没有题干与图片、没有年级/学期维度**。  
这三块不补，后面的「AI 讲解更清楚、公式好看、语音朗读、选择题」都只能锦上添花，无法形成真正的闭环。

## 1. 现状与差距（有代码依据）

### 1.1 已经有的

| 能力                | 位置                                               | 状态                                                    |
| ----------------- | ------------------------------------------------ | ----------------------------------------------------- |
| 错题池 + 生命周期        | `lib/models/review_model.dart`、`review_mistake`  | `pending → reviewing → verifying → mastered`，可用       |
| 手工录入（纯文字）         | `MistakeEditPage` + `addMistakeManually`         | 只有科目/标题/知识点/学生答案/错因，**没有题干与照片**                       |
| 讲解                | `/ai/review/explain`                             | 输入只有 `subject / knowledgePoint / title / wrongReason` |
| 举一反三              | `/ai/review/practice`                            | 只产出填空/解答题，**没有选项**                                    |
| 拍照作答              | `answerOcr` + `capturingAnswer`                  | 已支持                                                   |
| 组卷 / 打印 / 批改 / 报告 | `review_paper`、`review_attempt`、`review_summary` | 已有，报告偏统计                                              |

### 1.2 关键的四个缺口

1. **错题没有「题目本身」**
   - `homeworkCheck` 的返回条目只有 `knowledgePoint / originalAnswer / wrongReason`，没有题干；
   - 由此生成的 `ReviewMistake.title` 是「作业标题 · 知识点」，**不是题目**；
   - 讲解请求把 `title` 当题目发给模型。模型拿到的其实是一句标签，讲不具体是必然的。
2. **错题没有图片**
   - 错题来自照片批改，但图片属于 `homework_image`，与 `review_mistake` 没有关联；
   - 学生看不到「我当初错的那道题长什么样」，AI 也无法在读不懂题干时回看原图。
3. **手工录入是「事后补录」而不是「主动提交」**
   - 只能打字，不能拍试卷/作业；
   - 没有「来源」概念（作业 / 扫描 / 老师口述 / 自己整理），家长端无法区分可信度。
4. **没有年级/学期维度**
   - `app_user.grade` 存在且可编辑（`profile_page.dart`），但没有「学期」；
   - `review_mistake` 不记录录入时的年级，升年级后历史错题无法按「初一上」归档；
   - 列表只有科目筛选（`_subjectFilter`），没有学期筛选。

## 2. 目标闭环

```
                 ┌────────────── 录入（主动） ──────────────┐
                 │ ① 拍试卷/作业（多页）                      │
                 │ ② AI 拆题 → 学生勾选/改知识点              │
                 │ ③ 文字补录（老师口述、抄题）               │
                 └──────────────────┬───────────────────────┘
                                    ↓
   作业批改 ──→ 错题池（带题干、图片、来源、年级学期快照）
                                    ↓
                ┌─────────── 理解 ───────────┐
                │ AI 讲解（可看原图）+ 公式渲染 │
                │ 可选语音朗读                 │
                └──────────────┬──────────────┘
                               ↓
                ┌─────────── 验证 ───────────┐
                │ 举一反三：选择题直接点选     │
                │ 解答题：文字/拍照作答        │
                └──────────────┬──────────────┘
                               ↓
                作答证据 → 毕业判定 → 学期/知识点报告
```

**一条不变式**：讲解不构成毕业（看懂 ≠ 会做）；毕业只由 `review_attempt` 的证据决定。  
这条现有设计是对的，新增的录入与讲解能力都不许绕过它。

## 3. 数据模型

### 3.1 年级与学期

**学生档案**（`app_user` / 客户端 `app_user`）：

| 字段      | 类型   | 说明                    |
| ------- | ---- | --------------------- |
| `grade` | TEXT | 已有。值域不变：一年级…六年级、初一…高三 |
| `term`  | TEXT | 新增。`上` / `下`（空 = 未填写） |

为什么用两个字段而不是把「初一上」塞进 `grade`：

- 升学期只改 `term`，年级筛选、教材进度、报告口径都能独立使用；
- 用「初一上」当枚举会把**年级**和**学期**两个维度焊死，以后加「暑期」或「全年」就没有表达方式；
- 历史错题存的是**快照**，不随档案变化。

**排序与展示**：`gradeOrder = 一年级..高三 = 1..12`，`termOrder = 上 1 / 下 2`。  
筛选只做字符串相等，排序在客户端算，不往库里塞派生列。

**兼容**：`term` 为空时，UI 显示「未填学期」，筛选按「该年级全部学期」处理。

### 3.2 `review_mistake` 扩展

新增列（服务端 `011_mistake_intake.sql`；客户端 DB v24）：

| 列               | 类型      | 默认           | 用途                                         |
| --------------- | ------- | ------------ | ------------------------------------------ |
| `question_body` | TEXT    | `''`         | **完整题干**（可含 `$...$` LaTeX）                 |
| `answer_key`    | TEXT    | `''`         | 正确答案（可选；没有就不填，不猜）                          |
| `source_type`   | TEXT    | `'homework'` | `homework` / `scan` / `manual` / `teacher` |
| `grade`         | TEXT    | `''`         | 录入时年级快照                                    |
| `term`          | TEXT    | `''`         | 录入时学期快照                                    |
| `image_count`   | INTEGER | `0`          | 列表页显示角标，避免 N+1 查询                          |

**字段语义必须写清**（否则下一轮一定有人混用）：

- `title`：**短标题**，用于列表与组卷卷面。例：`「一元二次方程 · 第 3 题」`。
- `question_body`：**题目原文**。讲解、举一反三、组卷优先用它；为空才回退 `title`。
- `source_homework_title`：来源名称。作业批改填作业标题；扫描/手工填用户可改的来源名（如「十月月考」）。

**迁移规则（不许猜）**：

- `source_type`：`homework_id != ''` → `homework`，否则 `manual`；
- `grade/term`：**不回填**。历史错题如实标为「未归档」；
- `question_body`：**不回填**。`title` 是标题不是题干，拿它冒充题干会让讲解继续错下去；
- 讲解请求的取值顺序：`question_body` → `title`（并在 UI 提示「补全题干后讲解会更准」）。

### 3.3 错题图片 `review_mistake_image`

```sql
CREATE TABLE review_mistake_image (
  id          TEXT PRIMARY KEY,
  student_id  TEXT NOT NULL DEFAULT '',
  mistake_id  TEXT NOT NULL,
  storage_key TEXT NOT NULL DEFAULT '',
  mime_type   TEXT NOT NULL DEFAULT '',
  file_size   BIGINT NOT NULL DEFAULT 0,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_review_mistake_image_mistake ON review_mistake_image(mistake_id, sort_order);
```

设计要点：

- **与 `homework_image` 分表**，不共用。理由：作业图片的生命周期跟着作业走（重新批改会覆盖），  
  错题图片必须**独立于作业**存在——作业删了，错题还在。
- `storage_key` 沿用 `YYYYMMDD/<studentId>/<uuid>.<ext>`，与现有存储单点 `buildStorageKey` 一致。
- 上传复用现有签名端点 `POST /data/homework/images/sign-upload`（它只负责签名，不写作业表）。
- 读取新增 `GET /data/review/mistake-images/file?id=`，走 `readHomeworkImageBytes` 同样的字节读取逻辑，  
  但按 `review_mistake_image` 校验可见学生。
- RLS：与其余业务表同款 `app_rls` 策略，**必须 `ENABLE` + `FORCE`**。  
  新表最容易犯的错是「建了表忘了开 RLS」——那种越权在测试里完全看不出来。

### 3.4 `ai_practice_question` 扩展（选择题）

| 列               | 类型   | 默认       | 说明                               |
| --------------- | ---- | -------- | -------------------------------- |
| `question_type` | TEXT | `'text'` | `choice` / `text`                |
| `options_json`  | TEXT | `''`     | 选择题选项 JSON：`["A. ...","B. ..."]` |

`answer` 在选择题里存**选项键**（`A`/`B`/`C`/`D`），不存整段文字。  
理由：模型复述选项时很容易改一个标点，按整段文字比对会把做对的判成错的。

## 4. 第一步：错题录入

### 4.1 三种入口（同一个确认页）

| 入口         | 输入           | 适用           |
| ---------- | ------------ | ------------ |
| **拍题录入**   | 1–6 张照片      | 试卷、作业、练习册    |
| **文字录入**   | 题干/科目/知识点/答案 | 老师口述、自己抄题    |
| **作业批改转入** | 批改结果的错题条目    | 现有链路，补上题干与图片 |

### 4.2 拍题流程（状态机）

```
选图/拍照
  → 本地压缩 + 上传（失败：明确报错，不留半条）
  → POST /ai/review/extract-mistakes（视觉档）
  → 候选列表（可多选、可编辑、可合并/拆分）
  → 确认科目 / 知识点 / 答案 / 年级学期
  → 单事务写入：N 道错题 + 图片关联
  → 回到错题列表，定位到「刚录入」并高亮
```

**关键取舍：AI 只做「提取」，不做「判定对错」。**  
用户主动提交的是**他认为错的题**，不需要模型再判断一遍。  
让模型判断会引入一个无法解释的失败模式：模型说这题没错，用户就录不进去。

### 4.3 新 AI 接口 `POST /ai/review/extract-mistakes`

请求：

```json
{
  "images": [{ "mimeType": "image/jpeg", "data": "<base64>" }],
  "subjectHint": "数学",
  "grade": "初一",
  "term": "上"
}
```

响应：

```json
{
  "questions": [
    {
      "title": "第 12 题",
      "body": "解方程 $\\frac{x-1}{2} = \\frac{x+3}{3}$",
      "answer": "x = 9",
      "knowledgePoint": "一元一次方程 · 去分母",
      "pageIndex": 0,
      "confidence": 0.86
    }
  ]
}
```

约束：

- `answer` 允许为空串——**没有答案比编一个答案安全**；
- `confidence < 0.6` 的候选在 UI 标黄，默认不勾选；
- 一页识别不出多题时返回 1 条整页题，用户可手动拆；
- 模型分题能力必须用**真实试卷照片**验收（至少 10 张、含手写、含红笔批改），  
  不能只用干净印刷体。判据见 §9。

### 4.4 失败与事务

- **上传失败**：提示具体原因（网络/权限/格式），不创建错题行；
- **AI 失败**：保留照片，允许「先存为草稿」或「只填题干手写录入」；
- **写入失败**：单事务回滚，宁可一道都不进，也不留「有题没图」或「有图没题」；
- **重复提交**：用 `clientRequestId`（幂等键）避免用户连点两次生成两份。  
  现有 `insertMistakes` 没有幂等键，批量录入必须补。

### 4.5 从作业批改转入的补强

`homeworkCheck` 的条目增加**可选** `question` 字段（题干），提示词要求：  
「每道错题尽量抄下题干原文；看不清就留空，不要编。」  
`HomeworkCheckItem.question` 为空时，错题 `question_body` 留空，讲解回退 `title`。

同时把这次批改的图片按 `storage_key` 关联到生成的错题上（同一份作业的多道错题共享图片，  
`review_mistake_image` 允许多行指向同一个 key，不复制字节）。

## 5. 归档与筛选

### 5.1 默认视图

- 档案里有 `grade + term` → 默认只看**当前学期** + **未归档**；
- 档案没填 → 显示全部，并在顶部提示「设置年级后可按学期归档」。

为什么默认要带「未归档」：升级前已有 100+ 道错题，它们没有年级快照。  
只显示当前学期会让用户以为错题被清空了——这是最不能接受的失败形态。

### 5.2 筛选器

列表顶部（科目筛选之上）增加一行：

`[本学期 · 初一上 (23)] [全部 (108)] [选择学期…]`

「选择学期…」打开底部弹层：

- 按「年级 → 学期」两列展示，**只列出有数据的组合**，每项带数量；
- 支持多选；空结果给明确文案，不是空白页；
- 选择结果只存在内存，重新进入回到默认（避免用户忘了自己过滤过）。

### 5.3 归档

- 错题录入时写入 `grade/term` 快照；
- 编辑页允许修正（历史错题补录年级）；
- **不提供「批量改年级」**：批量改会把「当时几年级」这个事实变成可编辑的标签，  
  历史价值就没了。需要修正时逐题改。

## 6. 讲解升级

### 6.1 输入补全

`/ai/review/explain` 请求增加：

```json
{
  "subject": "数学",
  "knowledgePoint": "一元一次方程 · 去分母",
  "title": "第 12 题",
  "questionBody": "解方程 $\\frac{x-1}{2} = \\frac{x+3}{3}$",
  "wrongReason": "两边同乘 6 时漏乘右边",
  "grade": "初一",
  "term": "上",
  "images": [{ "mimeType": "image/jpeg", "data": "<base64>" }]
}
```

- `questionBody` 优先于 `title`；
- 有图时走**视觉档**，无图仍走 reasoning 档（成本差 8 倍，不能一律走视觉）；
- 网关新增 `reviewExplainVision` 能力映射，返回 schema 与文本版**完全一致**，  
  客户端不需要分支解析。

### 6.2 数学公式渲染

现状：`whyWrong / steps / pitfalls / mnemonic` 都是纯 `Text`，`\frac`、`x^2` 原样显示。

方案：

1. 提示词要求公式统一用 `$...$` 包裹的 LaTeX，例如 `$\frac{1}{2}x + 3 = 5$`；  
   纯文字不要包。
2. 新增 `lib/widgets/math_text.dart`：
   - 按 `$...$` / `$$...$$` 切分，公式段用 `flutter_math_fork` 的 `Math.tex`；
   - 普通段用 `Text.rich`，保留换行与中文排版；
   - **解析失败必须回退为原文**，并在旁边显示一个「公式未渲染」的小标记；  
     绝不能白屏或丢内容（这是本项目最忌讳的「静默失败」）。
3. 应用位置：错题详情（题干、讲解五段）、举一反三题干、组卷卷面（若导出 HTML 则后续单独处理）。
4. 依赖：`flutter_math_fork: ^0.7.4`（纯 Dart，依赖 `flutter_svg/provider/tuple`）。  
   已确认 pub.dev 可访问；引入后需跑一次完整构建，确认与 Flutter 3.47 兼容。

**风险**：模型可能输出 `\(...\)` 或裸 `x^2`。渲染器同时支持 `$...$`、`\(...\)`、`\[...\]` 三种定界符；  
裸表达式不做猜测（猜错比不渲染更糟）。

#### 6.2.1 「分数、平方能不能显示」取决于上游，不取决于客户端（10-19 核）

⭐ **渲染能力只对「模型输出了 LaTeX」的文本有效。** 实测两条（判据见
`test/math_text_test.dart` 末两条）：

| 输入 | 结果 |
|---|---|
| `计算 $\frac{3}{4}+\frac{1}{2}$ 的值` | 渲染出公式块，界面上**看不到** `\frac` 原文 |
| `计算 1/2 + 1/3 的值` | **0 个公式块** —— 它就是普通文字，客户端不会去猜哪里是分数 |

⚠️ 这条决定了排查方向：界面上出现 `1/2`、`x^2` 时，**先查模型写了什么**，
别去改渲染器 —— 渲染器再聪明也猜不出「1/2 是要显示成分式还是照抄」。

各链路的提示词覆盖情况（2026-10-19 核对）：

| 能力 | 提示词 | 位置 |
|---|---|---|
| `homeworkCheck`（作业拍照批改 → 题干进错题库） | ✅ 有，还点明了「纯文本在客户端渲染不出上下结构」 | `prompts.js` 第 6.1 条 |
| `extractMistakes`（拍照录入错题） | ✅ 有 | `prompts.js` 第 4 条 |
| `reviewExplain`（讲解） | ✅ 有 | `prompts.js` 末尾 ⚠️ 段 |
| `reviewTips`（计时页知识点提示） | ✅ 有 | `prompts.js` 第 5 条 |
| `reviewPractice`（举一反三出题） | 🔴 **原本漏了** → 已补（prompt + schema 字段说明） | `prompts.js` 末尾 + `schema.js` |

🔴 **补了 prompt 仍要重部署网关函数才生效**，而且**已经存进本地库的练习题
文本不会变**（那是历史数据，只能重新生成）。

⚠️ schema 的字段说明**不是注释**：它通过 `toTool()` 变成 function calling 的
参数描述发给模型，模型看得见。所以 `content` / `options` 的 description 里
也写了同一条要求 —— 这比提示词末尾的散文更硬。

#### 6.2.2 哪些字段**必须**走 `MathText`（2026-10-20）

用户第二次报「还是不支持公式」，根因不是渲染器，也不是提示词 —— 是
**同一页里一部分字段用了 `MathText`、另一部分还是纯 `Text`**。

错题详情页上，题干和五段讲解都渲染得好好的，唯独「当时的答案」和
「错因」两行是 `Text`。而这两行恰恰全是算式：

```
当时的答案：$2x$;$106.6-2.6x$
错因：第二空列式错误：当 $x>20$ 时，水费应为 $20 \times 2+(x-20) \times 2.6=…
```

⭐ **这类缺陷最容易被误判**：看截图的人以为「模型没写公式」，查渲染器的人
把 `MathText` 从头到尾看一遍然后说「没问题」—— 因为出问题的那两行
压根没走它。**「渲染器对不对」和「这段文本有没有进渲染器」是两个问题。**

判定规则（写新界面时照这个来）：**凡是可能含算式的文本字段，一律 `MathText`**。

| 字段 | 来源 | 已覆盖 |
|---|---|---|
| `mistake.title` | OCR / 批改 | ✅ 学生端列表、错题详情、家长端卡片 |
| `mistake.originalAnswer` | 学生作答 | ✅ 错题详情、家长端作业详情 |
| `mistake.wrongReason` | **模型** | ✅ 错题详情、学生端列表、家长端两处 |
| `item.summary`（批改总结） | **模型** | ✅ 学生端作业卡 |
| 讲解五段（whyWrong / steps / …） | **模型** | ✅ 错题详情 |
| `paperItem.questionTitle / questionBody / answerKey / studentAnswer / comment` | 组卷快照 | ✅ 学生端卷内预览、家长端卷内预览 |
| `practiceQuestion.*`（举一反三） | **模型** | ✅ 错题详情 |
| `reviewTips`（计时页提示） | **模型** | ✅ |

判据 `test/math_formula_render_in_mistake_test.dart`：
① 带 `$...$` 的错题，界面上**找不到 `$2x$` 原文**且出现 `Math` 块；
② 不带公式的错题照常显示（反面，防止判据恒绿）。

⚠️ 第 ① 条里「原文找不到」是核心，**不能只断言有 `Math` 块** ——
同一页的题干本来就带公式，只数 `Math` 的话，答案那两行退回纯文本也照样绿。

### 6.3 语音讲解

方案：**Android 系统 TTS**，通过 `MethodChannel` 调原生 `TextToSpeech`。

- 优点：离线、免费、无新增插件依赖，不增加构建风险；
- 位置：讲解页顶部一个「朗读讲解」按钮，播放中变「停止」；
- 语言：`Locale.CHINESE`；引擎缺失时明确提示「本机没有中文语音引擎」，  
  并给一条「去系统设置安装」的说明，**不静默失败**；
- 朗读前做文本清洗：去掉 `$`、LaTeX 命令，把 `\frac{1}{2}` 读成「二分之一」，  
  `^2` 读成「的平方」。清洗规则放独立函数并配单测；
- Web 端：`speechSynthesis` 可用则用，否则按钮置灰并说明原因；
- 范围：先做「整段讲解朗读」，不做逐句高亮。逐句高亮需要 TTS 回调对齐，  
  收益有限、复杂度高，放到后续。

#### 6.3.1 「声音生硬」是怎么来的（2026-10-19 追查）

**音色不在 App 里**。三层各管一段，越往下越改不动：

| 层 | 谁决定 | 在哪改 |
|---|---|---|
| 引擎 | 用户手机设置里的默认 TTS 引擎 | 手机系统设置；App **可以按包名指定**（`TextToSpeech(ctx, pkg)`），但写死包名 = 这台没装就初始化失败，各家 ROM 包名也不同 |
| 音色 voice | 引擎内部 | `MainActivity.selectPreferredVoice()` |
| 语言 / 语速 / 音调 | App | `MainActivity.configureLanguage()` |

原实现只调了 `setLanguage(SIMPLIFIED_CHINESE)` + `setSpeechRate(0.95f)` + `setPitch(1.0f)`，
**一次 `setVoice` 都没有** ⇒ 落在引擎自己的默认音色上，通常是 `QUALITY_NORMAL` 的离线包。
国产机常见的默认引擎（Google 语音服务 / 厂商自备）本身就偏机械，
低质量包听感更差 —— 这是「生硬」的第一个来源。

第二个来源在文本：`speak(整篇)` 一次性交给引擎，中文 TTS **在句号后不会真的停下来换气**，
一路念到底，听感就是念稿而不是讲课。

#### 6.3.2 改了什么

1. **自动挑最好的离线中文音色**：枚举 `TextToSpeech.voices`，剔除「需要联网」与「非 zh」的，
   按 `quality` 降序、同档优先 `zh_CN`（zh_TW 念数字和专业术语用台湾读法）。
   挑不到就保留引擎默认 —— **宁可难听，不能没声音**。
2. **按句朗读**：`speech_text.dart` 新增 `splitIntoSentences`，按 `。！？；` 与换行切句；
   超长句（模型吐出没有标点的大段文本）先在逗号处软切，切不动才硬切 ——
   从词中间砍会念出谁也听不懂的音，而且这种失败是静音的。
3. **句间留白**：原生侧一句一次 `QUEUE_ADD`，句子之间 `playSilentUtterance(300ms)`。
   只有最后一句用 Dart 给的 `utteranceId`，中间句子的回调被 Dart 侧的 id 配对判掉。
4. **可观测**：选定音色时打一条 logcat（tag `EasyLearnTts`：音色名 / quality / 候选数 / setVoice 返回码）。
   真机上**这是唯一能看见「到底选了谁」的地方**，没有它就是又一次静默失败。

**判据**（Dart 侧可自动化）：送进通道的必须是 `sentences` 数组而非整段，
且 `pauseMs > 0`；切句单测覆盖连续标点、换行、无标点超长句、软切位置。

**未验**：`selectPreferredVoice` 的实际选择只能在真机上看 logcat 确认
（widget 测试没有 Android 运行时，本机也没有 Android 设备）。

#### 6.3.3 让用户自己挑（10-19 下午）

自动挑只是**兜底**。真正能解决「这台手机的音色我都不喜欢」的，是把选择权交出去。

**入口在「个人信息设置 → 朗读设置」**（10-19 晚从讲解页朗读条挪过来的）。

原先挂在朗读条右侧的滑杆图标上，理由是「觉得难听的那一刻人正在这一屏」。但实际用下来
这个位置会传递一个错误的暗示：**每次朗读都要挑一次声音**。声音是一个人的长期偏好，
不该长成一次性动作。现在入口只留资料页这一处，选完存在 `SharedPreferences`，
重启 App 仍然生效（`PREF_ENGINE` / `PREF_VOICE` / `PREF_RATE`）。

面板内容：引擎列表 → 该引擎的中文音色列表 → 语速滑块，右上角「试听」。

⚠️ 入口**必须从资料页点得进去**才算数。`TtsSettingsTile` 能渲染、能弹面板，
都不代表资料页真的用了它 —— 判据在 `test/tts_settings_entry_test.dart`，
从 `ProfilePage` 点进去验（B38 的教训：机制建好了但调用点没接，界面上什么都不会发生）。

**四个必须做对的细节：**

1. **换引擎必须连音色偏好一起清**。音色名（如 `zh-cn-x-ccc-local`）只在**同一个引擎**内有效，
   换引擎后拿旧名字去 `setVoice` 只会失败或静默无效。`apply` 里 `engine` 一变就 `remove(PREF_VOICE)`。
2. **三个参数各有三态**：`null` = 这一项不动；`''` = 恢复系统默认；有值 = 用它。
   三者混成两态的话，「只换音色」会顺手把引擎写回默认 —— 这是最难在界面上发现的一类错。
3. **用户选的引擎可能已经不在了**（卸载 / 被禁用 / ROM 升级改名）。初始化失败时先清偏好、
   用系统默认重来一次（只一次）—— 否则朗读会**彻底没声音**，比难听糟得多。
4. **同档音色要能区分**。`zh-cn-x-ccc-local` 和 `zh-cn-x-xxx-local` 的最后一段都叫 `local`，
   只取最后一段会在列表里渲染出两行**一模一样**的选项：看着有得选，其实分不出选的是哪个。
   这里取最后两段拼起来。

**为什么另开一条通道**：`TextToSpeech.voices` 是**实例方法**，要拿到另一个引擎的音色，
只能为它临时建一个实例并等初始化回调（几百毫秒到几秒）。这不能发生在主线程。
所以 `cn.easylearn.app/tts-catalog` 挂在 `makeBackgroundTaskQueue()` 上，
`speak`/`stop` 仍留在主线程那条通道。

**判据**（`test/tts_settings_test.dart`，11 条）：通道参数形状（null 不出现 / `''` 显式出现）、
换引擎只写 engine、点音色只写 voice、短名不撞车、失败说原因而不是给空面板、非 Android 明确拒绝。
4 条证伪各**恰好** 1 红（第 4 条改过测试锚点：原来靠显示文字定位，会让连带红多一条；
改成 `ValueKey('tts-voice-<name>')` 之后才只红该红的那条）。

**未验**：真机上各厂商引擎的实际音色差异、`listVoices` 的真实耗时（6 秒超时够不够）。

#### 6.3.4 鸿蒙 / 卓易通：本地朗读在这类设备上不存在（10-19 晚）

真机反馈：鸿蒙手机，应用通过**卓易通**安装，朗读设置里报「这个引擎没有中文朗读能力」。

查证（华为开发者论坛 + 卓易通用户社区，2026-10 现状）：**鸿蒙 NEXT 不再包含 AOSP 的 TTS 服务**，
卓易通只模拟了部分安卓运行环境，**没有实现 `TextToSpeech` 那一层**。表现是
`TextToSpeech` 初始化回调返回非 SUCCESS、`voices` 为空、`setLanguage` 回
`LANG_MISSING_DATA / LANG_NOT_SUPPORTED`。**装中文语音包无效** —— 缺的是服务，不是数据。

⚠️ **原来的文案把三件事说成了一件事**。`listVoices` 里只要 `languageOk == false` 就抛
「这个引擎没有中文朗读能力」，而初始化失败也落在这个分支里。于是用户会照着
「去装中文语音包」折腾，那条路在这台机器上根本不存在。现在分成四个 code：

| code | 含义 | 下一步 |
|---|---|---|
| `engine_init_failed` | 引擎初始化就失败（容器里没有 TTS 服务） | 换设备；装包无效（见 §6.3.5：不走云端） |
| `language_not_supported` | 引擎能起来，但没有中文数据 | 装中文语音包 |
| `no_chinese_voice` | 引擎不报告任何中文音色 | 换引擎 / 装包 |
| `probe_timeout` | 6 秒没就绪 | 换引擎 |

**诊断行**：面板在出错时多显示一行事实 —— 厂商 + 型号 + Android 版本、引擎个数、
中文是否可用、初始化返回码。它不是为了好看：`引擎 0 个` / `初始化返回 -1` 是用户
唯一能自己判断「这条路在这台机器上不存在」的证据。

**失败隔离**：音色列表读不到只坏「音色」这一节，**引擎列表仍然可点**。
换引擎是这类机器上唯一可能有效的动作，原来整页变成错误页会把它藏起来。

**判据**（`test/tts_settings_test.dart`）：音色失败时引擎列表仍可点、
点下去真的写 `apply`；引擎为空时说明是系统缺服务并显示诊断事实。
证伪 2 条：① 让音色失败拖垮整个面板 → 3 红（同一机制被 3 条盯住）；
② 不渲染诊断块 → 恰好 1 红。

#### 6.3.5 决定：只用本地 TTS，不上云端合成（10-19 晚拍板）

**结论：不走云端。** 评估过百炼 CosyVoice（≈¥1/万字符，一道题讲解 ≈¥0.05），否决。

| 否决理由 | 说明 |
|---|---|
| 要新凭据 | 网关目前只有方舟（`ARK_*`），语音合成得另开一把 Key，多一条要轮换、要保管的秘密 |
| 持续成本 | 按学生量走，是个没有上限的月度支出；本地 TTS 是 0 |
| 隐私 | 讲解文本含学生做错的题、我的提示语，云端方案要把这些发到第三方；本地朗读一个字节都不出设备 |
| 复杂度 | 音频回传、缓存（按文本 hash）、播放器换实现，每一环都是新的静默失败面 |

**取舍后的兜底**：本地不可用时的正确反应是**降级，不是报故障** —— 见下一节。
真的一点点声音都出不来的机器（鸿蒙容器），讲解照常显示，只是没有朗读，
功能不被阻塞。

#### 6.3.6 降级：探测结论不再阻断朗读（10-19 晚）

⚠️ 这条修的是**上一轮自己挖的坑**。`configureLanguage()` 一返回 false
（`setLanguage` 报缺中文数据），整台机器就被判成不可用来 —— 于是语速、
音色、进度回调全没装，朗读彻底没声。可探测说「没有中文」的机器，
`speak` **往往照念不误**（鸿蒙/卓易通那类兼容层对 `setLanguage` 的返回值
实现得不标准）。**用系统默认的念出来，正是我们要的结果。**

⭐ **探测是探测、朗读是朗读**：探测的结论只能变成界面上的一句提示，
不能变成一道闸门。这条对整条链路都成立（音色列表取不到、引擎枚举不出来，同理）。

改动：

| 状态 | 含义 | 朗读 |
|---|---|---|
| `READY` | 中文数据、音色都按设置配上了 | 正常 |
| `DEGRADED`（新增） | 引擎能起来，只是没配上中文数据/音色 | **照念**，用系统默认 |
| `UNAVAILABLE` | 引擎根本起不来 | 失败，并说明是系统层面缺服务 |

顺带修掉一个**静默失败**：`engineState` 一旦落进 `UNAVAILABLE` 就再没有回到
初始化中的路径 —— 冷启动时系统 TTS 服务晚起来几百毫秒，这台机器上朗读就
**永久失效**，只能杀进程重启。现在 `handleSpeak` 遇到不可用会重建引擎重试一次
（`retryArmed` 防套娃，每建一个新实例给一次额度）。

⚠️ 实现时差点写错的顺序：先 `retryArmed = false` 再 `rebuildEngine()`。
而 `rebuildEngine()` 会把额度重置回 `true` —— 等于没清，失败会一路重建下去。

**判据**（`test/tts_settings_test.dart` 18 条）：降级时显示「正在用系统默认的声音
朗读」且不是故障页（引擎仍可点）；降级时换引擎仍写得下去；诊断行能分开
「系统没服务」和「只是没中文数据」；`status()` 读得出 `degraded`、老原生
不给这个键时按不降级处理。
证伪 4 条：① 撤掉降级提示条 → 恰好 1 红；② 把降级当故障 → 恰好 2 红；
③ 去掉诊断的降级分支 → 恰好 1 红；④ 服务层不读 `degraded` → 恰好 3 红。

### 6.4 讲解配图（2026-10-28）

讲解页「朗读讲解」下面多一块卡片：**点一下，把这道题画出来**。

#### 为什么不是"让模型画一张图"

图像生成模型画出来的几何图，**线长与标注数字对不上**：图上标着「a」的边可以是任意长度，
写着 50° 的角可以是 80°。学生照着这张图推理，会得出一个建立在错误前提上的结论 ——
而且它看起来完全正常，没有任何报错。

所以沿用举一反三那一套：**模型只给坐标（点和线），画由客户端做**。
坐标是数，长度由坐标算出来，标注写什么与线画多长由同一组数决定，画出来就不可能自相矛盾。
服务端用同一个 `normalizeFigure` 校验，任一处不成立就整张丢掉。

#### 「该不该画」才是这个端点的主要产出

初一错题里六成是有理数运算。给 `(-0.25)^2024 × (-4)^2024` 画一张数轴，
不只是没用 —— 它会挤掉讲解的位置，还让学生以为「图里有我没看出来的东西」。

所以契约里 `draw` 是**必填布尔值**，「不画」是**正当结论**，不是失败：

| 响应 | 含义 | 界面 |
|---|---|---|
| `draw=true` + figure | 画 | 卡片里显示图 |
| `draw=false`（`model_declined`） | 这题用式子讲更清楚 | 「这道题不画图」+ 理由 |
| `draw=false`（`figure_invalid`） | 模型画了但图对不上 | 「这张图没画对」+ 理由 |

后两者在界面上都是「没有图」，但只有第二种说明**配图质量在下降**。
混在一起，看板上一片安静，而学生那边已经很久没见到图了。

#### 两条硬护栏

1. **题干说「下图」「如图」但没有原题照片 ⇒ `draw=false`。**
   模型没见过那张图，画出来只能是编的 —— 学生一眼看出这不是他做的那道题，
   然后连上面那段讲解也一起不信了。带照片时走视觉档（`reviewFigurePhoto`）。
2. **没给绝对坐标不代表不能画。** 数轴题常说「到 B 的距离为 2」而不说 B 在哪
   （B 是上一小问给的）。这时把 B 放在 0、按相对关系定出其它点即可 ——
   学生要看的正是「距离为 2 有两个方向」。多个解必须**全画出来**。

#### 端点

```jsonc
POST /ai/review/figure          // 网关，AI_REQUIRE_AUTH 下需 Bearer token
{
  "subject": "数学", "knowledgePoint": "数轴上两点间的距离",
  "questionBody": "(2) 数轴上的点 C 与点 B 的距离为 2…",
  "images": [ /* 可选：原题照片，有则走视觉档 */ ]
}
// → { "draw": true, "reason": "…", "caption": "…", "figure": { "type": "coord", … } }
```

- 路由 kind：`reviewFigure` / `reviewFigurePhoto`（视觉档，配额 ×8）。
- **`reviewFigure` 必须进 `BAILIAN_THINKING_DISABLED_KINDS`**：开着思维链时
  真实错题 25s 超时（网关 `AI_MODEL_TIMEOUT_MS` 默认 25000），关掉后 1.5~5s。
  这与 10-27 打卡出题踩的是同一个坑。
- 客户端超时单独放宽到 30s / 40s（视觉），默认 12s 会把它静默掐掉。

#### 顺带修掉的一个老 bug

`FigureBounds.of()` 把 `top`/`bottom` 的初始化方向写反了（求最大值从 `+∞` 起），
导致边界恒为 ±Infinity、跨度恒为 1、投影出的 `offsetY` 是无穷大 ——
**画布上只剩一根坐标轴**，点和线全被画到可视区外。

这个 bug 从举一反三配图上线的第一天就存在，一直没人发现：
它不报错、不抛异常，看起来像「这张图本来就这么空」。
判据见 `test/practice_figure_bounds_test.dart`（旧写法 3 条全红）。

## 7. 举一反三：选择题

### 7.1 出题契约

`reviewPractice` 的每道题增加 `type` 与 `options`：

```json
{
  "type": "choice",
  "title": "第 1 题",
  "content": "下列方程中，解为 x=2 的是（ ）",
  "options": ["2x+1=5", "3x-1=4", "x/2=2", "4x=6"],
  "answer": "A",
  "difficulty": "基础"
}
```

**四种题型**（`choice` / `fill` / `judge` / `solution`），由模型**跟着错题本身的形式**决定：

- 原题是选择题 → `choice`；判断题 → `judge`；填空 → `fill`；其余 → `solution`。
- **不许为了「好批改」把解答题改成选择题** —— 换成另一种题型之后，学生练的  
  已经不是同一件事（这条写进了提示词，也有契约测试盯着）。
- `choice` 必须恰好 4 个选项、有且只有一个正确答案，`answer` 只填字母；
- `options` 只存选项内容，**不带 `A.` 前缀**（解析层统一剥掉，界面按序号渲染）；
- 客户端入库前校验：选项数 = 4、非空、不重复、answer 能归一成 A–D。  
  不合格的**丢弃该题并留一条降级记录**，不允许展示给学生，也不因此作废整组。

### 7.2 答题与判定

| 题型         | 作答         | 判定            |
| ---------- | ---------- | ------------- |
| `choice`   | 点选项（整行可点）  | **本地**比对字母    |
| `judge`    | 点「正确 / 错误」 | **本地**比对归一后的值 |
| `fill`     | 单行输入       | 模型            |
| `solution` | 多行输入 + 拍照  | 模型            |

- 填空**不**本地判：`0.5` 与 `1/2` 等价，字符串比对会把做对的学生判错。  
  省一次调用的代价是正确性，不做。
- 本地判定的结论标 `AiAnswerSource.rule`，与「模型挂了退到模板」的 `local`  
  分开 —— 混成一个值会让「选择题又快又准」被读成「这次模型挂了」。
- 错误选项同样写 `review_attempt`，走同一条毕业规则；**不得绕过**。

### 7.3 为什么值得做

- 选择题判定**确定**，不受模型波动影响；
- 单次练习成本从 3 次模型调用降到 0（选择题部分）；
- 学生操作从「打字/拍照」降到「点一下」，练习频率才可能上来。

## 8. 报告优化

现有报告（`review_report_page.dart` / `review_summary_page.dart`）是「数量 + 薄弱点 + 卷子列表」。  
建议按「先结论、后证据」重排：

1. **结论卡**：一句话说清「这学期错题 32 道，已掌握 21 道，还剩 11 道；最该练的是分数运算」。  
   这句话用规则生成，不额外调模型（可解释、零成本）。
2. **学期切换**：报告顶部与错题列表共用同一套学期筛选。
3. **趋势**：按周/月统计「新增错题 vs 掌握错题」。现有 `review_attempt.created_at` 足够算，不需要新表。
4. **薄弱知识点 Top 5**：按 `wrong_count` 加权、按最近错误时间衰减；每项带「去练」入口，  
   直接筛出该知识点的题。
5. **下一步建议（规则）**：
   - 连续两轮做对 → 「可以安排一次综合卷」；
   - 同一知识点 7 天内错 3 次 → 「建议先看讲解再练」；
   - 超过 14 天未复习 → 「有 N 道题在池里躺了很久」。
6. **AI 学情总结（可选，后续）**：一周一次、带缓存的自然语言总结。  
   必须标注「AI 生成」，且不能替代上面的硬指标。


## 10. 风险与未决项

| 风险                       | 影响                 | 对策                                          |
| ------------------------ | ------------------ | ------------------------------------------- |
| 视觉讲解的成本/延迟               | 单次是文本档的 8 倍配额、2–5s | 只在有图时走视觉；结果落 `explain_record`，同一题不重复调用      |
| 整卷拆题准确率                  | 拆错/漏题，用户不信任        | 候选可编辑、低置信度默认不选；用真实照片做 10 张验收                |
| 历史错题无题干                  | 讲解质量天然差            | 明确提示「补全题干更准」，提供快速补录入口                       |
| `title` 语义变化             | 全仓多处把 title 当题干    | 新增 `questionBody`，所有 AI 输入显式取值；`grep` 全部调用点 |
| `flutter_math_fork` 维护状态 | 未来 Flutter 升级可能不兼容 | 封装在 `MathText` 一个组件里，换实现只改一处                |
| 系统 TTS 引擎缺失              | 部分机型无声             | 启动时探测可用性，给出明确提示                             |
| RLS 新表忘开                 | 越权或查不到             | 迁移里 `ENABLE` + `FORCE`，并用两个学生账号做隔离测试        |
| 离线录入                     | 当前是本地优先架构          | P1 先保证本地库可写；同步队列沿用现有 bootstrap 机制           |

**需要产品确认的三件事**（见对话中的选项）：

1. 录入先做「一张照片一道题」还是直接做「整卷拆多题」；
2. 年级是否确认采用「年级 + 学期」两字段；
3. 语音用系统离线 TTS 还是暂缓。

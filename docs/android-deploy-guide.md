## 0 先搞清楚：要上云的只有一块

> ⚠️ **这一节描述的是「上云之前」的形态，已被取代**（见文件开头）。当年确实只有 AI 网关要上云；
> 现在数据服务也必须部署。**下面这张图与三条结论请当历史读**，
> 现状见 `doc/release-guide.md` 的部署总图。

这是整份文档最重要的一节。**如果理解错了这里，后面每一步都会做多余的工作。**

```
┌─────────────────────────┐
│  安卓手机（APK）          │
│  ├── 界面 + 业务逻辑      │   ← 完全在本地运行
│  ├── SQLite 数据库        │   ← 数据只存在这台手机上
│  └── 照片识别 / 批改       │
└───────────┬─────────────┘
            │ 只在这一条线上出网
            │ （编译期把 AI_BASE_URL 指向网关）
            ▼
┌─────────────────────────┐
│  云函数（AI 网关）        │   ← 唯一必须部署到云上的东西
│  持有 ARK_API_KEY        │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│  火山方舟（大模型）        │
└─────────────────────────┘
```

三条结论：

1. **业务数据不上云。** 作业、错题、积分全在手机的 SQLite 里（22 张表）。
   装了 APK 就能用，**一行云代码都不需要** —— 哪怕完全不配 AI，应用也是完整可用的。
   代价见 `doc/open-items.md` §C1：换手机数据不跟走。
2. **必须上云的是 AI 网关。** 唯一理由：**API Key 不能进客户端产物**。
   Web 端编译进 JS 打开控制台就能抄走，APK 可反编译提取 ——
   这不是「有风险」，是几天内必然被扫号脚本捞走，账单失控且查不到是谁用的。
3. **云数据库现在不需要。** 它是「要跨设备同步」时才出现的新功能，不是「部署现有的东西」。
   详见第 3 节。

所以下面第 1 节（装到手机）和第 4 节（接大模型）是**真要做的事**，
第 2 节是**要申请的东西**，第 3 节是**先别做的东西**。

## 1 把 APK 装到安卓手机

### 1.1 构建安装包

```bash
cd D:/workbuddy-project/projects/easy_learn_db
flutter build apk --release --no-tree-shake-icons \
  --dart-define=SEED_DEMO_DATA=true
```

⚠️ **`--dart-define=SEED_DEMO_DATA=true` 不能省**（这个包是**演示/自用包**，纯本地模式）。
从 2026-09-21 起，客户端**默认不灌演示数据** —— 因为真实用户第一次打开会看到
「林小宇 / 林小桐 / 王老师」这些**别人的孩子**，而且是**真写进库里的**。
漏了它，症状是**装完打开首屏一片空白**（不是崩、不是报错，就是什么都没有）。
开关的定义与「为什么默认关」在 `lib/services/demo_seed.dart`。

> **已在手机上的旧包不受影响**：演示数据是在首次启动时**写进本机库**的，
> 装过一次就一直在。只有**全新安装**（或清了应用数据）的新包才需要这个开关。

产物：`build/app/outputs/flutter-apk/app-release.apk`（约 55–58 MB，含三种 CPU 架构）。

`--no-tree-shake-icons` 不能省：项目里有动态构造的图标（`IconData`），
tree-shaking 会把它判成「没用到」而删掉，症状是**部分图标变成方框**。

> **本次已构建好一个可用包**，放在 `build/apk-share/easy_learn.apk`。
> 注意：在这之前 `build/` 里那个 11:58 的 release 包**是有 bug 的**
> （`UserModel.fromJson` 对空 `hobbies` 字符串调用 `List.from('')` 会崩，
> 症状是**手机号登录点了没反应/闪退**，而 Web 上不复现）。
> 如果手上还有那个旧包，删掉。

### 1.2 三条安装路径，按场景选

#### 路径 A：USB 数据线 + adb（调试首选）

能看日志，出问题能立刻定位，推荐用这个。

1. **手机开开发者选项**：设置 → 关于手机 → 连点「版本号」7 次 → 回到设置 → 系统 → 开发者选项 → 打开「USB 调试」。
2. **连线**，手机弹出「允许 USB 调试吗？」→ 勾选「一直允许」→ 确定。
3. 电脑上确认设备已授权：

```bash
adb devices
# 期望输出：
# List of devices attached
# 5XXXXXXXXX      device      ← 是 device，不是 unauthorized
```

4. 安装：

```bash
adb install -r build/app/outputs/flutter-apk/app-release.apk
# Success
```

`-r` 表示覆盖安装（保留数据）。

> 上面几步里 `unauthorized` 是最常见的卡点 —— 手机没点授权，或点了「拒绝」。
> 在手机的开发者选项里「撤销 USB 调试授权」再插一次即可。

#### 路径 B：手机浏览器直接下载（最省事，不用数据线）

1. 电脑上起一个静态服务，**绑局域网 IP**：

```bash
cd D:/workbuddy-project/projects/easy_learn_db/build/apk-share
"C:/Users/lp_pr/.workbuddy/binaries/python/versions/3.13.12/python.exe" -m http.server 8096 --bind 192.168.3.80
```

2. 手机连**同一个 WiFi**，浏览器打开：

```
http://192.168.3.80:8096/easy_learn.apk
```

3. 下载完成后点安装（会走「未知来源」授权，见 1.3）。

> 电脑 IP 变了（换 WiFi、重启路由）就换成新的：`ipconfig` 找无线网卡的 IPv4 地址。
> 连不上先看第 5 节的排障表 —— **本机 `curl` 能通不代表手机能通**。

#### 路径 C：微信 / QQ 传文件

适合远程给别人的手机装。

- **不要用微信直接发**：微信对 `.apk` 有安全策略，可能被拦截或改成 `.apk.1` 让手机认不出来。
- 稳妥做法：用**QQ 传文件**，或把 APK 打成 zip 再发，对方解压后安装。
- 传到手机后，用手机自带的文件管理器找到它 → 点击安装。

### 1.3 「未知来源」开关（Android 8 以上是**按应用**授权的）

不是全局开关，而是「允许**哪一个应用**安装 APK」：

设置 → 应用 → 特殊应用权限 → **安装未知应用** → 找到你用的那个
（浏览器 / 文件管理器 / QQ）→ 允许。

各家 ROM 路径不同，直接**在设置里搜「未知应用」**最快。

### 1.4 签名与「覆盖安装」（一个必须知道的坑）

> ⚠️ **已过期（2026-09-22）**：现在**不再是 debug 签名**。
> release 构建会读 `android/key.properties` 用真 keystore 签名；
> 只有**没配密钥的机器**才回退 debug 并大声警告。真包已用
> `apksigner verify --print-certs` 验过（DN=`CN=BanXue`）。
> 下面这段保留，是因为它解释的**现象**（「应用未安装 / 签名不一致」）在
> 「换台电脑构建」或「换过 keystore」时依然会遇到。
> 生成与备份见 `doc/release-guide.md` §1。

**当年 release 包用的是 debug 签名**（`android/app/build.gradle.kts`：
`signingConfig = signingConfigs.getByName("debug")`，Flutter 模板默认，原文带 TODO）。

这意味着：

| 场景 | 结果 |
|---|---|
| 自己手机装、内部测试 | ✅ 完全没问题 |
| 上架应用商店 | ❌ 必须换成正式签名（release keystore） |
| **同一台电脑**构建的新包覆盖安装旧的 | ✅ 可以，数据保留 |
| **换一台电脑**构建的包覆盖安装 | ❌ 报「应用未安装」，因为 **debug key 是跟机器走的**，签名不一致 |

遇到「应用未安装 / 与已安装应用签名不一致」，**先卸载旧的应用再装**（数据会一起清掉）。

正式签名怎么做（等要上架时再执行）：

```bash
keytool -genkey -v -keystore ~/easy-learn-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias easy-learn
```

然后把 `signingConfigs` 指向它。**这个 keystore 文件和密码丢了就再也无法更新已发布的应用**，
备份好。

应用第一次打开会**自动写入演示数据**（`DatabaseService.seedIfEmpty()`）：

| 角色 | 手机号 | 密码 |
|---|---|---|
| 学生 | `13800000001`（林小宇） | `abc123` |
| 学生 | `13800000003`（林小桐） | `abc123` |
| 家长 | `13800000002`（王老师） | `abc123` |

> 演示数据是**自己测试用的**。交付给真实用户前必须处理
> （`doc/open-items.md` §C6）—— 否则用户第一次打开就会看到「别人的孩子」。

**没配 AI 网关时**：拍照识别、批改、讲解会走**本地模拟实现**
（`SimulatedAiDataSource`，确定性假数据），界面照常可用，不会报错。
所以「AI 好像没生效」不一定是你配错了 —— 先看第 4 节。

### 1.6 装完的验收动作

按顺序做一遍，能把大部分问题挡在早期：

1. 打开应用 → 看到登录页（而不是白屏/闪退）。
2. 用 `13800000001` / `abc123` 登录 → 进学生首页。
   **这一步是登录 bug 的回归点**，崩了就是装了旧包。
3. 进「复习」→ 有错题；进「积分」→ 有账本记录 = **本地数据库真的在手机上工作了**。
4. 拍照识别一条作业（真机才测得准，模拟器是虚拟相机）。

## 2 云空间怎么申请

### 2.1 为什么主推火山引擎

| 理由 | 说明 |
|---|---|
| **AI 在方舟** | 模型用的是火山方舟，函数和方舟**同一个账号** —— 少一套账号体系、少一张账单 |
| **代码就是为它写的** | 网关 README 明确写了 veFaaS 的部署方式（运行时、入口、触发器），腾讯云 SCF / 阿里云 FC 也兼容（事件形状一致），但 veFaaS 是原配 |
| **必须同区域** | 方舟数据面在**北京**，函数也要在北京。跨区往返的几十毫秒会**逐次叠加**（一次批改要调用若干次模型），而这段延迟正好落在「学生点提交后盯着屏幕等结果」这个最敏感的窗口里 |

### 2.2 账号与实名

1. 打开 `volcengine.com` → 右上角注册（手机号即可）。
2. **完成实名认证**（个人认证：身份证 + 人脸；企业认证：营业执照）。
   **这一步不能跳** —— 不做实名**无法开通任何模型服务**，后面会一直卡在「开通失败」。

### 2.3 要开通哪些服务

| 服务 | 用途 | 是否必须 |
|---|---|---|
| **火山方舟** | 大模型服务平台 | ✅ 必须 |
| **函数服务 veFaaS** | 跑 AI 网关代码 | ✅ 必须 |
| **API 网关** | 给函数一个公网 HTTPS 域名 | ✅ 必须 |
| 对象存储 TOS | 存照片（外链模式用） | ❌ 不用（默认内联模式） |
| 云数据库 RDS | 存业务数据 | ❌ 暂不需要（见第 3 节） |

**两个容易卡住的授权步骤**：

1. **首次使用函数服务要完成「跨服务授权」** —— 没授权时控制台会弹引导页，跟着点完即可。
2. 如果用的是**子账号**，需要主账号授予
   `VeFaaSFullAccess`、`APIGFullAccess`、`STSAssumeRoleAccess` 三个策略，否则建不了函数。

### 2.4 费用大致怎么算

三部分独立计费，都是**按量后付费**（不用预充值）：

| 部分 | 计费方式 | 量级参考 |
|---|---|---|
| 函数服务 | 调用次数 + 运行时长 + 出网流量 | 量小时费用很低 |
| API 网关 | 调用次数 | 同上 |
| **方舟（大头）** | 按 token，输入/输出分别计价 | 项目 README 记的单价：视觉 **3 / 9**、强推理 **0.8 / 4.8**、轻量 **0.3 / 0.6** 元每百万 token（输入/输出） |

**粗算一次拍照批改**：视觉档，输入约 2000 token、输出约 700 token（这个输出量是实测的）
→ `2000/1e6 × 3 + 700/1e6 × 9 ≈ ¥0.012`，**大约一分钱一次**。

**每个学生每天的上限**由网关的 `AI_QUOTA_UNITS_PER_DAY`（默认 200 单位）封住，
按上面单价换算约 **¥0.3/天/学生** —— 注意这是**用满**的量级，不是平均数。

> 具体价格以控制台定价页为准，上表是照项目里记录过的单价算的，用于判断量级。

## 3 云数据库怎么部署

> ⚠️ **本节已被取代（2026-09-22）**：云数据库**已经是现状**，
> 而且它**不是**「新增一套服务端数据层」，是**已经写好的那份**（26 表 + RLS + 九组仓库的云端实现）。
> 上线要做的是「把它部署出来」：建库 → `node scripts/migrate.mjs --yes` → 配角色口令 →
> 部署数据服务。**照 `doc/release-guide.md` 第 2 节做，不要照本节做。**
> 下面保留的是当年的选型论证与「Serverless 连接数坑」，那部分**仍然有效**。

### 3.1 结论：现在不需要，而且它不是「部署」问题

**这个应用没有云端数据库。** 所有数据在手机的 SQLite 里（22 张表）。

所以「在云空间上部署数据库」这件事，**当前不存在可部署的对象** ——
它不是「把现有的库搬上去」，而是「新增一套服务端数据层」。这两件事的工作量差一个量级。

**什么时候才需要**：出现下面任一需求时。
- 换手机要能看到旧数据；
- 家长用自己的手机看、孩子用另一台手机做
  （现在的 `relationship` 表把两者绑在**同一个本地库**里，做不到。**代码级证据与演进路径见 `multi-device-architecture.md`**）；
- 老师/多端看同一份数据。

### 3.2 真要做的话，缺的是三件套

不是一个数据库，是三件：

| 组件 | 为什么必须有 |
|---|---|
| **① 服务端登录** | 没有身份，就无从谈起「这是谁的数据」。现在客户端账号体系是**纯本地**的（`open-items.md` §A2） |
| **② 云端库 + 同步协议** | 存不是难点，**合**才是（见下） |
| **③ 客户端从「本地唯一真相」改成「本地缓存 + 服务端权威」** | 这是**架构级改动**。`DatabaseService` 现在被当作唯一数据入口来设计，查询内置 `studentId` 过滤，改造面很大 |

**建议的顺序**：先做 ①（服务端登录），再评估 ②③。
没有身份的服务端数据库，只会把「数据在谁的手机里」变成「数据在谁都没管的表里」。

**动手之前先看 `architecture-refactor-plan.md`**：里面对应的是「三段分层」与迁移顺序，另有一份
**五个「本地不炸、上云才炸」的陷阱**清单 —— 最典型的是积分幂等：本地靠数据库唯一索引兜底，
换成云端 API 后这条防线必须由服务端重新提供，否则会**静默重复发分**（不报错，只表现为「分不对」）。

### 3.3 选的型（真到那一步时）

| 方案 | 适合 | 代价 |
|---|---|---|
| **A. 云厂商托管数据库**（火山 RDS PostgreSQL/MySQL）+ 在网关里加同步端点 | 想自己掌控数据、要强的查询能力 | 要处理 VPC、连接数、迁移与版本 |
| **B. BaaS**（云开发的数据库直接给客户端 API） | 想少写后端、快速上线 | 把数据访问能力开放给客户端，安全全押在「规则」上 |
| **C. 不做同步，只做备份/导出** | 只要「别丢数据」 | 最省事。客户端已有导出能力（`ReviewExporter` 打印/下载 HTML），加一条「导出数据文件」即可 |

**如果走 A，有一个 Serverless 特有的坑必须先知道**：
函数的实例数会弹性伸缩，**每个实例都建自己的数据库连接** →
`实例数 × 连接数` 很容易打爆数据库的连接上限，症状是高峰期大面积超时。
对策是用**连接池代理**（云厂商一般都有），或改用 HTTP 接口的数据库。另外冷启动时建连有额外延迟。

### 3.4 最难的不是「存」是「合」

多设备同步真正的成本在**冲突解决**。这个项目的表可以粗分两类，策略完全不同：

- **账本类**（`point_ledger`）：**天然好合**。它是 append-only 的，
  每笔都有 `idempotencyKey` 和 `reversalOf`（撤销靠冲正，不删记录）——
  所以合并就是「按 id 去重后求并集」，不会丢也不会重复计分。
  这套设计本来是为防刷做的，顺带也让同步变简单了。
- **状态类**（`homework` 的批改结果、`wish` 的兑现状态）：
  两台设备各改一次，**用「最后写入的赢」会静默丢操作** ——
  家长在 A 手机批改了，孩子在 B 手机又提交一次，回来一看批改结果没了。
  这类要带**版本号或操作日志**，而不是比时间戳。

**顺序建议**：先把账本类同步跑通（它的正确性容易验证），
状态类留到后面单独设计 —— 混在一起做，出问题时无法判断是哪一类错了。

## 4 连接 AI 大模型

这一节是「让 AI 真的生效」的完整路径。做完第 1 节应用能用，做完这节**AI 才用得上**。

### 4.1 方舟侧：开通清单

1. **注册 + 实名认证**（同 2.2，不做实名开不了模型）。
2. 进控制台 → **火山方舟**服务 → 按提示开通（按量后付费，**无需提前充值**）。
3. **创建 API Key**：左侧「API Key 管理」→ 创建 → **立即复制保存**。
   ⚠️ 页面刷新后**再也看不到明文**，丢了只能删掉重建。
4. **逐个开通模型**：进「模型广场」→ 找到目标模型 → 点「立即开通」。
   ⚠️ **方舟不是「拿了 Key 就能调所有模型」**。没开通的模型会返回
   `ModelNotOpen` 或 404 —— **看起来像「模型不存在」，其实是没开通**。
   这是新手最常踩的一个坑。
5. **创建推理接入点**（推荐）：「在线推理」→ 创建推理接入点 → 选刚开通的模型 → 复制 **Endpoint ID**（`ep-` 开头）。

> **`ep-` ID 和模型 ID 的区别**：调用时 `model` 字段填 `ep-xxx` 最稳。
> 填错会返回 404 或 "model not found"，**根本到不了鉴权那一步** ——
> 所以遇到 404 先别怀疑 Key，先检查模型标识。

区域固定北京，接入地址：

```
https://ark.cn-beijing.volces.com/api/v3
```

（这是网关的默认值，一般不用手动配。）

### 4.2 三个档位分别填什么

网关有三级能力位，对应三种不同成本的模型（`ARK_MODEL_VISION` / `REASONING` / `LIGHT`）：

| 环境变量 | 用途 | 选型要求 |
|---|---|---|
| `ARK_MODEL_VISION` | 作业拍照识别、手写批改 | **必须真多模态**（要能读图） |
| `ARK_MODEL_REASONING` | 错题判定、讲解生成、出题 | 强推理 |
| `ARK_MODEL_LIGHT` | 文本解析、格式化 | **当前没有任何业务端点用它**（`open-items.md` §A3） |

**两条硬规矩**：

1. **留空 = 该能力未开通。** 网关会**如实**回 `model_not_enabled`，
   客户端探到 `capabilities.vision = false` 后**根本不发图**，直接走本地识别。
   这是正确行为，不是故障。
2. **没有的档位就留空，绝对不要拿同一个模型名填满。**
   把纯文本模型填进视觉档**不会报错** —— 它只会**编一份批改结果**，
   而那份结果会进错题库、被组卷、被打印出来让孩子重做。

> 判据来自实测：本机 `gemma4:e4b` 在 `/api/show` 里**声明支持 vision**，
> 实际回答「我无法看到图片」。所以**能力要实测，不要信声明**。

### 4.3 把网关部署到函数服务

要上传的东西是 `serverless/ai-gateway/` 整个目录，**不需要 `npm install`**
（`dependencies` 是空的，只用 Node 内置模块 + 全局 `fetch`）——
这也是它能在 Serverless 上冷启动快的原因。

**关键配置项**：

| 配置 | 填什么 | 为什么 |
|---|---|---|
| 函数类型 | **事件函数** | 网关的形状是「事件 → 响应」，不是常驻 Web 服务 |
| 运行时 | **Node.js 20+** | 用到了全局 `fetch` |
| 入口 | `index.cjs` 的 `handler` | `index.cjs` 是 CommonJS 垫片（平台若认 ESM 可指 `src/handler.js`） |
| 区域 | **北京** | 与方舟同区域，理由见 2.1 |
| 超时 | **≥ 60s** | 模型调用本身要 10–30s，默认超时会让请求在模型返回前被掐断 |
| 触发器 | 直连 FC3 HTTP 触发器即可（`s.yaml` 就是这么配的） | 服务会自己抹掉 `/ai/` 之前的前缀，所以**只要事件里的 path 还含 `/ai/` 就行**。⚠️ 前面再挂 API 网关并做了路径重写时必须保住这一段 |
| CPU / 内存 | **0.25 vCPU / 512MB** | 纯网络等待，CPU 用不满。⚠️ 只填 `memorySize` 有坑：FC3 要求 `cpu : 内存(GB)` 落在 1:1~1:4，256MB 只在 cpu ≤ 0.25 时合法，随手配 0.5 核 → `InvalidArgument` |

**环境变量**（在函数配置里设，**不要写进代码**）：

```
ARK_API_KEY=<你的 Key>              ← 必填
ARK_MODEL_VISION=<视觉档 ep-xxx 或模型 ID>
ARK_MODEL_REASONING=<强推理档 ep-xxx 或模型 ID>
ARK_MODEL_LIGHT=                     ← 没有就留空
AI_REQUIRE_AUTH=false                ← 先保持 false，理由见下
```

**两个自检会在启动时直接抛错**（它们的失败方式都是静默的，所以做成了硬失败）：
- `AI_QUOTA_UNITS_PER_DAY` 小于最大权重（视觉档默认 8）→ 那一档一次都跑不了；
- 单价 `AI_PRICE_*` **只填了一部分** → 未配的那部分会被算成 0，
  总额偏小，**而这个偏小的数字看起来是完整的**。
  **要么全填、要么全空**（不留任何 `AI_PRICE_*` 即可）。

> **`AI_REQUIRE_AUTH` 为什么先保持 false**：客户端账号体系目前是纯本地的，
> 拿不到服务端签发的会话 token。打开它 → **客户端全部 401**。
> 这是设计使然（宁可拒绝，也不放行一个可伪造的身份）。
> 此期间网关用 `X-Student-Id` 做配额与审计，但**它可以被伪造，不构成强鉴权**。
> **对外上线前必须**先做服务端登录再打开它（`open-items.md` §A2）。

部署完成会拿到一个公网域名，形如：

```
https://xxxxxxxx.apigateway-cn-beijing.volceapi.com
```

### 4.4 让客户端指向网关

网关地址通过**编译期常量**注入：

```bash
flutter build apk --release --no-tree-shake-icons \
  --dart-define=AI_BASE_URL=https://xxxxxxxx.apigateway-cn-beijing.volceapi.com
```

⚠️ **`AI_BASE_URL` 是编译期常量，改地址必须重新构建 APK** ——
不能像配置文件那样在手机上改。这是刻意的：它挡住了「把厂商地址填进去」这种错误
（填厂商地址就意味着 API Key 要进客户端产物）。

**其余可选开关**（大多数情况不用动）：

| 开关 | 默认 | 什么时候动 |
|---|---|---|
| `AI_TIMEOUT_MS` | 12000 | **只有接本机模型时才调大**。云端模型的耗时是稳定的，调大只是把「模型一句话都不回」的等待一起放大 |
| `AI_UPLOAD_TIMEOUT_MS` | 30000 | 同上 |
| `AI_CAP_VISION` / `AI_CAP_REASONING` / `AI_CAP_LIGHT` | true | 强制关掉某一级 |
| `AI_DISABLED` | false | 紧急止血：置 true 后客户端完全走本地实现，不发任何请求 |

### 4.5 验收（**这一步不能跳**）

**① 先看网关活着**：

```bash
curl https://<你的网关域名>/ai/health
```

返回里关注 `capabilities`（三级能力是否 true）和 `quota.dailyCalls`。
注意：**健康检查只反映配置**（有没有 Key、模型 ID 填没填），
**不反映方舟那边是不是真的开通了** —— 所以还要做 ②。

**② 用真凭证探活**：

```bash
cd serverless/ai-gateway
ARK_API_KEY=<你的 Key> \
ARK_MODEL_VISION=<视觉档> ARK_MODEL_REASONING=<强推理档> \
node scripts/probe-ark.mjs
```

**退出码 0 才算通过。** 它做两件本地怎么测都测不出来的事：

1. 确认三级模型**确实已开通**（不是「配置填了」）；
2. **核对 `usage` 的字段名** —— 网关的成本链路只认
   `usage.prompt_tokens` / `usage.completion_tokens`。
   方舟某个模型若换了字段名或干脆不返回 usage，**看板不会报错**，
   它只会安静地把 token 记成 0、让成本退化成「下限」。

**③ 端到端**：手机装上新构建的 APK → 拍照识别一条作业 → 看结果是不是真的识别出了内容
（而不是本地模拟数据）。也可以看网关日志里的审计行：

```bash
grep '"path":"/ai/homework/ocr"' gateway.log | tail -3
```

- `"ok":true` 且 `latencyMs` 几百毫秒以上 → **模型真的跑了**，问题在识别质量；
- `"ok":false` 且 `latencyMs:0`、`model:null` → **请求根本没到模型**，是入口校验拦下的，看 `code`。

### 4.6 「AI 没生效」的排障顺序

按这个顺序查，能省掉一半时间 —— **先查身份，再查模型**：

| 现象 | 最可能的原因 |
|---|---|
| 完全没有 AI 反应，但应用不报错 | **没配 `AI_BASE_URL`** → 走的是本地模拟实现，这是默认行为 |
| 提示「AI 不可用 / 降级」 | 网关地址错、APK 是没带 `--dart-define` 的旧包、或者出网被拦 |
| `bad_request` | 看审计里的 `studentId`：是 `anonymous` 说明**未登录**就发起了调用；是 `unknown` 说明请求头真没带；是真实学号才是请求体不对 |
| 识别质量差 / 结果离谱 | 模型档位填错（比如文本模型填进视觉档）、或照片本身不合格 |
| `model_output_invalid` | 模型没按 schema 输出。**网关刻意不替模型补空** —— 补空就会把「这不是作业」变成一份假批改结果 |
| 一直 `model_timeout` | 函数超时设太短（要 ≥60s），或模型档位配得太慢 |

### 4.7 一条**放最后但最重要**的提醒

**方舟的 Key 一旦泄露，会在几小时内被扫号脚本跑光额度。** 所以：

- Key **只出现在函数的环境变量里**，不进任何返回体与日志；
- 不要为了图省事把 Key 写进客户端（`AI_BASE_URL` 不能填厂商地址，就是这个原因）；
- `AI_UPLOAD_SIGNING_SECRET` **不要复用 `ARK_API_KEY`**。

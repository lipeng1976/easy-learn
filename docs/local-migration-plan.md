## 一、先回答：能不能用「本地豆包」

**不能。** 豆包（Doubao）是字节的**闭源商业模型**，官方明确不开放权重下载与本地部署授权，
只通过火山方舟 API 对外提供服务。所谓「豆包开源」指的是 `Seed-OSS` 这类**实验性组件**，
与支撑豆包 App 的那批模型不是一回事。

```
豆包 Pro / Lite / Vision  →  闭源 · 只有 API  →  ARK_* 那一套
Seed-OSS 系列            →  开源（但不是豆包主力能力）
```

所以「AI 全本地」只有一条路：**换开源模型，跑在本机 Ollama 上**。
你的机器已经装了 Ollama，而且**项目里早就把这条路实测过了**（见 §2.2）。

### 三条路，先把代价摆出来

| | AI 在哪跑 | 是否依赖外网 | 金钱成本 | 实测批改 / 讲解 | 代码改动 |
|---|---|---|---|---|---|
| **L1 全本地** | 本机 Ollama 26B | ❌ 不依赖 | 0 | **27.4s / 36.5s**（讲解超 12s 窗口） | **0**（只改配置） |
| **L2 混合** | 视觉走本机、文本走 API | ✅ 部分 | 现有 | 视觉 27s（慢）/ 文本 <6s | 0 |
| **L3 全 API** | 本机网关 → 百炼 / 方舟 | ✅ 全部 | 现有 | **2.0s / 5.6s** | 0（网关切配置） |

> L2 只在「后台停了但 API 还能用」时成立。你要求的是**全部本地**，本文按 **L1** 展开，
> 但把 L2 留作兜底（§8 回滚）。

### ⭐ 2026-10-18 实测纠正：L3（本机网关 + 云端模型）是可行且最优的

你说的「客户端的豆包，分析试卷和讲解都很好，有没有可能用这种方式」——
**可以，而且这条路比换本地模型好得多。** 关键在于把两件事拆开：

```
「后台搬本机」  = 账号/作业/错题/附件 存在你的 PC，网关跑在你的 PC   ← 解决「云服务停了」
「模型搬本机」  = 推理算力也搬到本地                                  ← 解决「断网也能用」+「零费用」
```

**只有第二个才需要 26B 那种慢模型。第一个不需要动模型。**

实测（同一台机器、同一套网关代码、同一个请求，只换后端）：

| 后端 | 批改 `/ai/homework/check` | 讲解 `/ai/review/explain` | 结果 |
|---|---|---|---|
| 本机 26B（Ollama） | 27.4s（中位） | 36.5s | ✅ 正确 |
| **本机网关 → 百炼 `qwen3.5-omni-plus`** | **2.0s** | **5.6s** | ✅ 正确（score=60、两条错题） |
| 本机网关 → 方舟 `doubao-seed-2-1-lite` | ❌ 429 | ❌ 429 | **账户额度用尽，服务被暂停** |

两条重要事实（都是查出来的，不是猜的）：

1. **线上当前跑的不是豆包，是百炼。** 线上 `/ai/health` 回 `modelProvider: "bailian"`、
   `.env.prod` 里 `BAILIAN_MODEL_VISION=qwen3.5-omni-plus`。
   你感受到的「豆包很好」，实际是 `qwen3.5-omni-plus` 在干活。
2. **豆包那条路现在是断的**，原因不是技术：方舟返回
   `429 ... has reached the set usage limit for the [doubao-seed-2-1-lite] model, and the model service has been paused`
   ⇒ 账户额度用尽。要用豆包得先去方舟控制台提额度（这也是当初切百炼的原因）。

⇒ **推荐 L3**：数据与后台 100% 搬本机（P1–P4、P6），**P5「AI 切 Ollama」整段跳过**，
网关保持默认配置打向百炼，一行代码不改，体验与今天线上完全一致。
代价只有两条：仍需外网、仍按 token 计费。**不适用**于「要彻底断网 / 要求推理零费用」的场景 ——
那种情况下只能接受 L1 的讲解降级。

> ⚠️ 隐私边界：L3 下题目照片仍会发给模型厂商。如果这条不能接受，才必须走 L1。

### 额度与成本实测（2026-10-18，`usage` 取自网关响应，价格取自百炼官方计费页）

**一次真实批改的 token 账单**（`qwen3.5-omni-plus`，同一张 5 题作业页）：

```
输入 4122 tokens（其中图片 2147 + 提示词 1975）
输出  133 tokens（思维链已在名单里关掉）
```

| 档位 | 单价（输入/输出，元/百万） | 单次批改成本 | 实测耗时 | 实测正确性 |
|---|---|---|---|---|
| `qwen3.5-omni-plus`（线上在用） | 7 / 40 | **≈0.034 元（3.4 分）** | 2.1s | ✅ **两次均 score=60 · 2 条错题全中** |
| `qwen3.5-omni-flash` | 2.2 / 13.3 | ≈0.010 元 | 1.6–2.2s | 🔴 **两次结果都不对**：一次多报（3 条）、一次**漏报**（只抓到 1 条，6×8=42 被判对） |

**⭐ flash 不能用于批改，别为省 2 分钱引入漏报。** 漏报的后果是「孩子做错了却被判对
→ 错题不进错题库 → 家长看不到问题」，这比任何成本都贵。ground truth 已人工看图核实：
5 题中恰好 2 错（9×3=26、6×8=42），plus 与本地 26B 均全中。

**每月账单（家庭自用口径）**：

| 使用强度 | 月成本 |
|---|---|
| 每天 3 次拍照检查 | **≈3 元** |
| 每天 10 次 | ≈10 元 |

**免费额度**：百炼给 `qwen3.5-omni-plus` **100 万 tokens / 90 天**（官方计费页），
按单次 4255 tokens 折算 ≈ **235 次批改** —— 每天 3 次能用约 78 天，基本覆盖有效期。
过期后每月 3–10 元，**额度不是这条路的阻塞项**。

**方舟（豆包）侧**：429 的直接原因是此前一次性赠送额度（每模型 50 万 tokens）耗尽。
恢复路径有二：控制台查看「协作奖励计划」（第三方资料称个人可领每日 200 万 tokens/单模型，
**以控制台实际展示为准，未实测**）；或直接充值 —— Seed 系列价格低于百炼 omni-plus
（第三方称 Turbo 输入 3 / 输出 15 元/百万）。两家的 Key 与模型名在 `.env.prod` 里都已配好，
切换只动 `AI_MODEL_PROVIDER` 一个变量。

**结论：本地能顶「作业」这条线，顶不住「讲解」。**

## 四、六个阶段

> 每个阶段都有「判据」。**判据不通过不许进下一阶段** —— 这是本项目的老规矩：
> 「全绿」不构成判据，必须**证伪**（把修复还原后恰好那几条变红）。

### P0 · 选型预检（不改任何东西）

**目的：在动数据之前，确认 AI 到底能到什么水平。**

| 动作 | 命令 / 位置 | 产出 |
|---|---|---|
| 测现有模型是否仍满足 tool_calls + 读图 | `node scripts/probe-ollama.mjs` | 一张当前实测表 |
| 试拉一个**专用小 VLM**（7B 级，能全放 12GB 显存） | `ollama pull qwen2.5vl:7b`（或 `qwen3-vl:8b`，以能拉到的为准） | 比 26B 快多少 |
| 用同一批手写样本量识别率 | `node scripts/measure-handwriting-ocr.mjs <dir> stu_001 L4` | 与 26B 对照 |
| 盘点云上数据规模 | 连云 RDS 数一遍 26 表行数 + 附件总数 | 迁移窗口估算 |

**判据：**
- 候选 VLM 必须**真读到图**（不能只看 `ollama show` 的 `vision` 声明 —— `gemma4:e4b` 就是反例）
- 必须给出 L1–L4 四档召回，不能只测工整样本

**⚠️ 待实测（我不编）：** `qwen2.5vl:7b` 在**中文手写**上的表现我没有数据，
可能比 26B 差很多。这一条必须在 P0 用 L4 样本打出来，否则不要选它。

### ✅ P0 实测结果（2026-10-18，真跑，不是推的）

**测法**：`e2e-local-homework.mjs` + `make-homework-photos.ps1` 生成的作业页，
网关指向本机 `gemma4:26b`（三档同模型），走真 HTTP 端点。

**第一轮（网关默认 25s 超时）：7 条链路全部 `model_timeout`。**
连纯文本判定都超时 —— 这个结果本身就说明「默认配置接本机模型」是不可行的。

**第二轮（单独测批改，超时放宽到 180s）：成功，但慢。**

```
status=200  elapsed=50.5s
score=60
items[0] 9 × 3 = 26 → "结果算错了，应该是 27"
items[1] 6 × 8 = 42 → "结果算错了，应该是 48"
summary "共有 2 处乘法计算错误。"
completion_tokens=1387（大半是思维链）
```

**⭐ 能力结论：具备。** 两道故意做错的题**全部抓到**，且给出的正确答案是对的，
不是「没报错」那种假成功。这回答了你问的「本地模型能不能做错题检查」——**能**。

**⚠️ 速度结论：50.5s，超客户端带图窗口 30s。**

**瓶颈定位（这一步比结果更重要）：**

```
显存 12227 MiB 总 · 已用 10918 MiB · 空闲 1027 MiB
占用者：douyin.exe（抖音，GPU 利用率 0% —— 只是占着显存）
     └─ Ollama 的 llama-server 只拿到 size_vram ≈ 1.2 GB
```

26B 权重 18.6GB，**只有 1.2GB 进显存，其余 17GB 跑在 CPU 上** ⇒ 50s 完全解释得通。
这不是模型不行，是**显存被别的程序吃掉了**。

### 第三轮（2026-10-18 关掉抖音后 · 对照实验）

关掉抖音后显存从 `10918 已用 / 1027 空闲` 变成 **`0 已用 / 11944 空闲`**，
预热 26B 后 Ollama 拿到 **10.7 GB**（此前 1.2 GB），只剩 1.2GB 空闲给系统。

先跑一轮三条链路（同一张图、title 加后缀绕缓存）：

| 链路 | 显存被占（1.2GB 给模型） | **显存全空（10.7GB 给模型）** | 客户端窗口 | 判定 |
|---|---|---|---|---|
| 批改 `/ai/homework/check` | 50.5s | **31.1s** | 30s | ⚠️ 差 1.1s |
| 判定 `/ai/review/judge` | 10.3s（README） | **11.4s** | 12s | ⚠️ 余量 0.6s |
| 讲解 `/ai/review/explain` | 42.6s（README） | **36.5s** | 12s | ❌ 仍超窗 |

批改单次采样贴着窗口线，不能下结论，于是**同一张图连跑 3 次**（每次换 title 绕缓存）：

```
第1次 30.5s   score=60  items=2  cached=false
第2次 23.2s   score=60  items=2  cached=false
第3次 27.4s   score=60  items=2  cached=false
中位 27.4s · 4 次采样里 2 次到/超 30s
```

**⭐ 关掉抖音的净效果：批改 50.5s → 23–31s（中位 27.4s，约快 45%），
结果 4/4 完全一致**（score=60、两道错题全抓到、答案对）。

**但余量薄到不能用**：慢的那次 31.1s，最快 23.2s —— 同一台机器同一张图，
**抖动 8 秒**。真实手机拍照（更大分辨率、更糊）只会更慢。这不是「能用了」，
是「刚好卡在窗口线上」。

**新瓶颈已经不是显存，而是下面两条：**

1. **26B 权重 18.6GB > 12GB 显存**，即便显存全给它，仍有约 8GB 在 CPU 上跑
   ⇒ 这是型号本身的硬账，清多少后台程序都改不了。
2. **思维链吃掉大半出参**（`completion_tokens=1387`，批改只要几十个 token 的结果）
   ⇒ 讲解 36.5s 的主因。关掉能砍一半以上（方舟实测 23.5s → 6.8s），
   但 ⚠️ 网关**没有**给 Ollama 发 `think:false` 的通道 —— `thinking` 是方舟私有字段，
   README 明确要求「指向本机 Ollama 时该名单必须留空」，这条路**要改代码**。

⇒ 优化方向（按性价比排序，前两条已实测，后两条未测）：

| # | 动作 | 预期 | 代价 |
|---|---|---|---|
| 1 | 关掉占显存的程序（已做） | 批改 50.5→27.4s | 0（但不能要求用户每次先关抖音） |
| 2 | **换 7B 级 VLM** | 权重能全放显存，预计 10s 内 | **手写识别率未测**，必须先用 L4 样本量 |
| 3 | 给 Ollama 补 `think:false` 通道 | 讲解 36.5s 有望进 12s | 改网关代码 + 按厂商分支 |
| 4 | 放宽客户端超时 | 直接「通过」 | 失败时用户干等；且判定/讲解窗口是产品口径，不宜为模型让步 |

> ✅ 顺带排除一个候选：本机已有的 `gemma4:e4b`（8B）试读同一张图，
> **200 但内容为空**（token 全耗在 thinking 里），且换入要与 26B 抢显存。
> 不作为候选。

> 📌 另注：`OLLAMA_CONTEXT_LENGTH=65536` 会额外吃 KV cache 显存。改成 8192 能再腾出一些。

### P1 · 本机 PostgreSQL 落地（不做数据迁移）

**为什么不用现成的 embedded PG 17：**

1. 它是**开发组件**，不是服务：没有崩溃恢复、备份、大版本升级路径
2. 版本是 **17**，云上是 **18.4** ⇒ `pg_dump` 18 的产物恢复进 17 会失败
   （PG 不保证向下兼容，且本项目 `sql/` 里有 18 才有的写法风险）

**动作：**

| # | 动作 | 说明 |
|---|---|---|
| 1 | 装 **PostgreSQL 18**（Windows 官方安装包，服务形式） | 端口建议 **5432**，与云上一致，减少变量 |
| 2 | 设 `data_directory` 到 **D 盘**（如 `D:\pgdata18`） | 避免系统盘 |
| 3 | 记录 `pg_dump` / `psql` 的绝对路径 | 后续脚本要用，**本机原先没有 psql** |
| 4 | 建库 `easy_learn` + 跑 `provision-app-roles.mjs` → `migrate.mjs` | 顺序不能反 |
| 5 | 开 `pg_stat_statements` / 设 `max_connections ≥ 100` | 单机够用 |

**判据：**
- `SELECT version()` 显示 **18.x**
- `\dt` 数出 **26 张表**、`pg_policies` 数出 **25 条 RLS 且全部 FORCE**
- 用 `easylearn_admin` 能连、用 `app_rls` 连时**看不到**别人孩子的数据（跑 `probe-rls.mjs`）

**回滚：** 卸载服务、删数据目录，云端一切未动。

### P2 · 数据迁移（云 RDS → 本机 PG 18）

**这一步是「搬」，不是「同步」。** 搬完之后两套库再无关系。

#### 动作

| # | 动作 | 关键细节 |
|---|---|---|
| 1 | 停写窗口 | 先让客户端别再写（或接受「搬完之后手机上新增的那几条丢失」）|
| 2 | `pg_dump` 云库 | 用 **PG 18** 的 `pg_dump`，`--no-owner --no-privileges`；**不要 `-c`**（目标是空库）|
| 3 | 恢复到本机 | 用 **`easylearn_admin`**（带 `rolbypassrls`）执行 —— 用应用角色恢复会被 RLS **静默挡掉一部分行** |
| 4 | 重置序列 | `setval` 逐表对齐 `max(id)`，否则新插入撞主键 |
| 5 | 校验 | 逐表行数 + 最老记录日期 + 抽样 JOIN（见判据）|

**云库连接信息**：沿用既有约定 —— `PGHOST_EXTERNAL`（外网端点）+ `PG_OPS_USER/PASSWORD`，
读取走 `serverless/scripts/lib/env-file.mjs` 的 `cloudHost()`。
⚠️ 云上的 `PGHOST` 是**内网**地址，本机连不上；内网/外网是两个域名，实例 ID 尾部差两个字符。

⚠️ RDS 白名单要放行**家里当前公网 IP**，而家宽 IP 可能变。

#### 判据（缺一不可）

- 26 张表**逐表**行数一致（打印成一张对照表，不一致就停）
- **最老一条记录的日期不变**（这是「没漏数据」的唯一硬判据，总数对不上可以解释，最老日期变新只能是被删）
- `homework` / `homework_image` / `review_*` 抽样 JOIN 不出孤儿行
- 用**应用角色**登录客户端，能读到自己孩子的历史作业（不是只测 admin）

#### 回滚

云端库**只读不动**，随时可以退回去（重出云端包的配置还在）。

### P3 · 附件迁移（OSS → 本地盘）

**这条比数据容易，因为键格式天然对齐。**

`buildStorageKey` 生成的是 `${YYYYMMDD}/${studentId}/${uuid}${ext}`，
本地 fs 后端读的时候是 `path.resolve(IMAGE_ROOT_DIR, storageKey)`
⇒ **只要把 OSS 对象按它自己的 key 原样存到本地目录，代码零改动就能读到。**

#### 动作

| # | 动作 | 说明 |
|---|---|---|
| 1 | 从库里取全部 `storage_key` | `SELECT storage_key FROM homework_image ...`（含音频/视频附件表）|
| 2 | 列举 OSS 对象 | 现有 `ossimagestore.js` **没有 list 能力**，需按 V4 签名写 `ListObjects`（可复用 `signRequest`）|
| 3 | 逐个下载并落盘 | 保持 key 路径；已存在且大小一致就跳过（可断点续传）|
| 4 | 校验 | **读回逐字节一致**，不是「文件存在」 |

#### 判据

- 库里 key 总数 = 本地文件数（差一个都要查）
- 抽样 20 个文件 **sha256 与 OSS 一致**
- 走一次真读链路：`probe:media-bytes` 指向本机，能取回照片/音频/视频
- ⚠️ **大视频**：云上 `sign-read` 受函数 32 MiB 响应体限制（B32 的「传得上去、取不回来」）；
  **本地 fs 没有这个限制** ⇒ 迁到本地后这个问题自动消失（这是本地化的意外收益）

#### 回滚

本地附件目录删掉即可，OSS 原件不动。

### P4 · 后台常驻（从「脚本」变成「服务」）

`dev-stack.mjs` 的注释写得很明白：它是**前台交互脚本**，且**必须在无沙箱隔离下运行**。
不能直接拿来当服务。

#### 方案（推荐 A）

| | 方案 | 优点 | 缺点 |
|---|---|---|---|
| **A** | Windows 服务（`nssm` 或 `sc.exe`）+ PG 18 服务 | 开机自启、崩溃重启、日志落盘 | 需要装一个包装器 |
| B | 计划任务（开机启动 + 失败重启） | 不装东西 | 重启策略弱、无标准日志 |

**要跑三个东西，顺序固定：**

```
PostgreSQL 18 服务  →  数据服务 :8788  →  AI 网关 :8787
```

**新增文件（不改现有逻辑）：**

| 文件 | 作用 |
|---|---|
| `serverless/local/start-data.mjs` | 读 env → 起数据服务（非交互、日志到文件） |
| `serverless/local/start-ai.mjs` | 同上，起网关 |
| `serverless/local/health-local.mjs` | 探活：PG / 8788 / 8787 / Ollama，四路各自报 |
| `serverless/local/backup.mjs` | `pg_dump` + 附件目录增量复制到**另一块盘** |

#### 判据

- **重启机器**后 60 秒内三样都起来（不是「手动 start 能起来」）
- 杀掉数据服务进程 → 服务自动拉起（证明「崩溃重启」不是空话）
- 拔网线 → 数据服务仍可用、AI 仍可用（证明真的本地化）
- 每天自动备份跑过一次，且**能从备份恢复**（只生成文件不算）

#### ⚠️ 已知坑

- `dev-stack` 被沙箱回收时症状是「起来几秒后自己没了」—— 包成服务时这个坑会以
  「服务启动后立刻停止」重现
- `embedded-postgres` 的 `pg.stop()` 在 Windows 上会挂住 —— P1 换成真 PG 后这条不再适用

### P5 · AI 切到本机 Ollama

> ⭐ **若选 L3（本机网关 + 云端模型，§1 推荐），本阶段整段跳过。**
> 网关保持默认配置打向百炼即可，不需要 `ARK_BASE_URL` 覆盖、不需要挑 VLM、
> 也不受 §2.2 所有速度限制。下面的内容仅在「要求彻底断网 / 推理零费用」时执行。

**这一阶段代码零改动。** 全部是环境变量（README §接本机模型 已经验过）。

#### 动作

| # | 变量 | 值 | 为什么 |
|---|---|---|---|
| 1 | `AI_MODEL_PROVIDER` | `ark`（保持） | 借 `ARK_*` 这组槽位；**不是**真用方舟，只是复用命名 |
| 2 | `ARK_BASE_URL` | `http://127.0.0.1:11434/v1` | 换后端 |
| 3 | `ARK_API_KEY` | `local` | ⚠️ **不能留空**：`capabilities()` 把「有 Key」当能力可用的必要条件，留空 ⇒ 三级全报 `model_not_enabled` |
| 4 | `ARK_MODEL_VISION` | P0 选出的 VLM | 必须**实测能读图** |
| 5 | `ARK_MODEL_REASONING` | `qwen2.5:7b` 或 `gemma4:26b` | 见 §2.2 的取舍 |
| 6 | `ARK_MODEL_LIGHT` | `qwen2.5:7b` | 便宜够用 |
| 7 | `ARK_THINKING_DISABLED_KINDS` | **留空** | 方舟特有字段，Ollama 可能直接 400 |
| 8 | `AI_PRICE_*` / `ARK_PRICE_*` | **全部留空** | 本机无单价；只填一部分会被 `validateConfig` 拦下 |
| 9 | `AI_KV_DRIVER` | `memory` | 单实例正确选择 |
| 10 | `AI_ALLOW_EPHEMERAL_KV` | `true` | 生产守卫要求显式确认；⚠️ 一旦多开进程，配额立刻失真 |
| 11 | `AI_REQUIRE_AUTH` | `true` | 局域网里也是真实账号数据 |
| 12 | `AI_SESSION_SECRET` | 与数据服务**同一把**、≥32 字符 | 不一致 ⇒ 网关全 401 |

#### 三个「填错也不报错」的坑（README 原文）

1. **视觉档别拿文本模型顶上** —— 它不会报错，只会**编一份批改结果**，
   而那份结果会进错题库、被组卷、被打印出来让孩子重做。
2. **单价要么全配要么全空**，半配会在启动时直接抛错（这是故意的）。
3. **`thinking` 名单留空** —— 这是方舟私有字段，不是 OpenAI 协议的一部分。

#### 判据

- `/ai/health` 的 `capabilities` 三级全 `true`，且 `modelProviderEnv` 指向 `ARK`
- **真图**跑一次批改（不能只测文本）：两张故意做错的作业照片 → 两道都抓到
  ⚠️ 这是 B29 的入口：只发文本、或发一张空白图，会得到 `score:100 items:[]`，
  看起来「全对」，实际是**把错题库清空了**
- **负对照**：发一张纯空白图 → 必须显式失败（或 `score:100 + items:[]` 且明确告知），
  不能安静地当成「全对」
- 断网后仍能批改（证明不依赖云）

### P6 · 客户端重出包 + 端到端验收

**这一步不是零改动 —— 有一处安卓配置必须改。**

### 🔴 先解决：明文 HTTP 会被系统拦掉

`android/app/src/main/res/xml/network_security_config.xml` 现在**只放行两条回环地址**：

```xml
<domain includeSubdomains="false">127.0.0.1</domain>
<domain includeSubdomains="false">localhost</domain>
```

它是为 just_audio 的本地代理加的。而本机后端是 `http://192.168.3.80:8788` ——
**不在白名单里，`targetSdk=36` 会直接拒绝请求**。

症状极具误导性：**请求根本不发出去**，界面上表现为「一直转圈 / 连不上服务」，
后端日志**一条都没有** —— 会让人以为是服务没起或防火墙。

**要加的是本机在局域网里的地址**：

```xml
<domain includeSubdomains="false">192.168.3.80</domain>
```

⚠️ 因此 **IP 必须固定**（路由器按 MAC 绑定）。IP 一变 = 这条配置失效 = **必须重出包**。
用 `<base-config cleartextTrafficPermitted="true">` 全局放行更省事，但那是把
「一处回环」放开成「所有 http」—— 与现有注释里刻意做的取舍相反，不建议。

> iOS 侧同理（ATS），但 `ios/` 从未构建过，本次不涉及。

### 再构建

⚠️ **不能直接跑 `tools/build-cloud-apk.mjs`** —— 它有三道闸门：
拒绝私有网段、**强制 https**、构建前探活。它是为云包设计的。
本地包要手写命令（或给它加 `--allow-local` 开关，属可选改造）：

```bash
flutter build apk --release \
  --dart-define=DATA_API_BASE_URL=http://192.168.3.80:8788 \
  --dart-define=AI_BASE_URL=http://192.168.3.80:8787 \
  --dart-define=AI_TIMEOUT_MS=90000 \
  --dart-define=AI_UPLOAD_TIMEOUT_MS=120000
```

> `AI_TIMEOUT_MS` 默认 12s、带图 30s。**放宽到 90s 是本地大模型的必要补偿** ——
> 26B 的讲解实测 42.6s，不放宽就必然降级。代价是「失败时用户要等更久」。

#### ⚠️ IP 必须固定

`192.168.3.80` 是 DHCP 分的，**路由器重启后可能变**，那时手机会「连不上」而
看起来像「服务挂了」。⇒ 在路由器上给这台机器绑定静态 IP（按 MAC）。

#### 判据（按顺序，少一条都不算完）

1. 装新包，**用云端库已有的账号登录**（不是注册新号 —— 验证数据真的搬过来了）
2. 看到历史作业/错题（证明 P2 成功）
3. 打开一张历史作业的照片（证明 P3 成功）
4. 拍一张新作业 → 批改成功，且**错题真的进了错题库**
5. 错题讲解能用（⚠️ 这就是会降级的那条 —— 要么等 40s，要么接受走本地模板）
6. 杀掉 App 重开 → 记住密码仍然生效（B37 回归）
7. 关掉 PC 的网卡 → 数据服务仍可用、批改仍可用（证明全本地）

## 七、风险清单

| 风险 | 概率 | 症状 | 处置 |
|---|---|---|---|
| **讲解超时降级** | **必然** | 用户点了讲解，等 12s 什么都没发生 | 放宽客户端超时到 90s，或接受降级并如实提示 |
| **显存被别的程序占** | **高（本机已撞到）** | 同一模型突然慢 3 倍（50.5s vs 16.4s） | 跑前 `nvidia-smi`；关抖音/浏览器；或固定用 7B |
| **判定余量只有 1.7s** | 高 | 偶发「判定失败」→ 错题不毕业 | 判定档单独用小模型（`qwen2.5:7b` 实测 4.2s） |
| **潦草手写认成通顺错词** | 中 | 作业内容看着正常其实错了 | 已有 `uncertain` + 客户端 ⓘ 标记，**不要删** |
| **拔网线后仍走云** | 中 | 以为本地化成功，其实还在发云请求 | 断网测试必须真拔（或防火墙断），不能只看日志 |
| **明文 HTTP 被系统拦** | **必然**（不改一定撞） | 请求根本不发，界面转圈，**后端零日志** | 在 `network_security_config.xml` 放行局域网地址（P6） |
| **IP 变了连不上** | 高（DHCP） | 「服务挂了」 | 路由器绑定静态 IP |
| **PC 休眠/重启** | 中 | 晚上关机，早上连不上 | 电源计划设「从不休眠」+ 服务开机自启 |
| **单盘故障** | 低但致命 | 数据 + 附件全没 | 每日备份到**另一块盘**（同一块盘不算备份） |
| **AI Key 仍留在配置里** | 低 | 本地跑着但 Key 还在 | 切本地后把 `BAILIAN_API_KEY` 移除，避免「以为本地、其实云」 |

## 八、回滚

| 阶段 | 回滚方式 | 代价 |
|---|---|---|
| P1–P4 | 停本地服务，手机装回云端包 | 零（云端未动） |
| P2 之后 | 云端库**只读不动**，随时可退 | 本地期间产生的新数据**不会回传** |
| P5 | 把 `ARK_BASE_URL` 改回云地址 | 需要 Key 与计费 |
| 全部 | 用 `archive-2026-10-13` 的 bundle 重建 | 代码回到 10-13 状态 |

> ⚠️ **回滚不是双向同步。** 没有「本地写入自动回流云端」的机制，也不建议做 ——
> 那会变成一套双向同步的运维负担。

## 九、需要你拍板的四件事（不拍板我没法进 P1）

1. **AI 走哪条路？**
   - L1 全本地（讲解会降级，但彻底不依赖外网 / 不花钱）
   - L2 混合（视觉走本机，讲解走 API，体验最好但没完全本地）
   - L3 全 API（现状，只是把后台搬回本机）

2. **手机要不要在外面也能用？**
   - 只在局域网 ⇒ 零额外工作（本文按这个写）
   - 要出门可用 ⇒ 需要组网/穿透（Tailscale 之类），多一个 P7

3. **云上的历史数据要不要搬？**
   - 搬 ⇒ 走 P2，有停写窗口
   - 不搬 ⇒ 从零开始，但**账号、作业、错题全部丢**

4. **能接受多大延迟？**
   - 维持 12s ⇒ 讲解不可用
   - 放宽到 90s ⇒ 讲解可用，但失败时用户要干等
